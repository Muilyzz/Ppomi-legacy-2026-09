# 사업자 공동인증서 발급 플레이북 검증 — 2026-09-09

세움터 사업자 가입의 인증서 준비를 위해 사용자가 공동인증서 발급 플레이북으로 전환하도록 지시했다. 기존 `eais` 가입 상태와 승인 범위는 유지하며, 인증서 발급 완료·세움터 인증 성공·회원가입 완료는 각각 별도로 확인한다.

## 패키지 검증 결과

`joint-certificate` v0.1.0을 원본 Catalog에 추가하고 생성 번들 및 로컬 설치본에 반영했다. 선언된 manifest와 guide만 원자적으로 로컬 설치했으며 기존 플레이북·발자국은 변경하지 않았다. 실행 중 MCP의 `read_playbook(app: "공동인증서 발행")`이 새 패키지를 반환했고, 반환된 guide가 원본과 정확히 일치했다. 실행 증거의 저장 단계·재생 단계·재생 성공·실패는 모두 0이다.

총 22개 테스트가 통과했다. 이는 패키지 구조·조회·설치 계약 검증이며 실제 인증서 발급 성공을 뜻하지 않는다. 앱 실행 파일 전체를 교체하거나 재시작하지 않았다.

## 확인한 경로

기존 사업자 인터넷뱅킹 은행이 있다면 그 은행의 공식 기업 인증센터를 먼저 확인한다. 계좌 보유만으로 기업뱅킹 가입 여부나 인증서 발급 자격을 추정하지 않는다. 최초 은행 질문 이후 사용자가 KB라고 답해 KB 경로를 선택했다. 유료 인증서 상품은 선택하지 않았다.

은행 경로가 없을 때 검토할 한국정보인증의 공식 비대면 안내를 21:14 KST에 기존 Parallels Windows 11의 Edge 새 탭으로 열었다. 공식 URL, 사업자 범용 상품, 부가세 별도 가격 표시를 화면으로 확인했다. 상품 선택·신청서 제출·개인정보 전송·결제·발급은 수행하지 않았다. 기존 세움터 탭은 유지했다.

공식 자료에서 확인한 내용은 다음과 같다. 금액·상품·요건은 실행 당시 공식 화면에서 다시 확인한다.

| 경로 | 확인한 내용 | 아직 확인하지 않은 내용 |
|---|---|---|
| 기존 기업뱅킹 인증센터 | IBK는 금융거래용 공동인증서 1년 4,400원, 범용 1년 110,000원(VAT 포함)을 안내한다. 금융거래용에는 전자민원이 포함된다. | 사용자의 가입 은행·기업뱅킹 상태, 세움터가 수락하는 현재 인증서 정책 OID |
| 한국정보인증 비대면 | 1인 대표 개인사업자 본인 신청. 휴대폰·본인 계좌·신분증 및 신청일 포함 7일 이내 사업자등록증명원 필요. 1년 범용은 100,000원+VAT. | 사용자 자격, 실제 신청·검토·결제·발급 결과 |
| 한국전자인증 비대면 | 1인 대표 개인사업자 또는 법인 대표자 본인 신청. 외국인·공동대표·대리 신청 제외. 법인은 7일 이내 법인등기사항전부증명서 추가. 공식 안내상 검토·발급 안내 최대 1영업일. | 사용자 자격, 실제 신청·검토·결제·발급 결과 |

전자세금계산서 전용은 공식 은행 안내상 세금 업무용이므로 이 작업의 신규 발급 후보에서 제외한다. 세움터가 해당 인증서를 기술적으로 반드시 거절한다는 검증은 아니다. 범용도 발급기관의 넓은 용도 안내만으로 세움터에서 실제 인증에 성공했다고 기록하지 않는다.

한국정보인증은 정부24 앱의 전자문서지갑으로 주민등록번호 전체 표시 사업자등록증명원을 한국정보인증에 보내도록 요구한다. 이 민감한 제출과 실제 본인 인증은 해당 공식 화면에서 당사자가 처리한다. 원문 서류·주민등록번호·OTP·암호·개인키·발급코드는 이 문서나 플레이북에 기록하지 않는다.

## 실행 환경과 남은 단계

현재 Windows 도구는 화면 읽기와 키보드·마우스 제어를 사용한다. 게스트 Edge DOM/CDP 연결은 구현·연결되지 않았다. 공개 페이지의 웹 문서 읽기를 게스트 DOM 제어 성공으로 보고하지 않는다.

KB 기업 인증센터를 21:19, 인증서 관리 화면을 21:21~21:22에 기존 Parallels Edge에서 확인했다. 관리 화면에는 공동인증서 가져오기·내보내기·복사 경로가 표시됐다. 사이트의 로컬 앱·서비스 접근 권한 요청은 허용하지 않고 닫았다. 새 발급·재발급·복사 거래나 개인정보 입력은 실행하지 않았다.

사용자가 기존 발급 인증서에 미치는 영향을 질문해 KB 공식 FAQ를 확인했다. 다른 PC에서 같은 인증서를 재발급하면 기존 인증서가 자동 폐기된다고 안내한다. 이후 사용자가 이 영향을 허용하고 KB 발급·재발급 및 새 인증서의 USB 복사 플레이북을 명시적으로 요청했다. 기존 인증서 보관 위치 질문은 더 이상 진행 조건이 아니며 같은 재발급 허가를 다시 묻지 않는다. 실제 기존 인증서 폐기·재발급은 아직 실행하지 않았다. 발급 후에도 세움터에서의 용도·정책 수락과 실제 인증 결과는 별도로 확인한다.

이 내용을 공개 패키지의 KB 재사용 분기로 추가해 v0.1.1로 올렸다. 생성 검사 4/4를 다시 통과했고 로컬 패키지를 원자적으로 갱신했다. 원래 v0.1.0은 임시 검증 디렉터리에 보존했다. 새로운 실제 발급·재생 성공 기록은 없다.

## KB 발급·재발급 및 USB 복사 확장

v0.2.0 원본에 `kb-issue-or-reissue`와 `copy-certificate-to-usb`를 추가했다. 이미 허용된 KB 발급·재발급 준비를 이어가고, USB가 없으면 Windows PC 저장 후 USB 연결 시 복사를 재개한다. 실제 Windows USB 연결과 원본·대상 인증서 목록을 별도로 확인하며 포맷·삭제·덮어쓰기를 자동 처리하지 않는다. 실제 인증서 파일·개인키·암호나 사용자 관계 정보는 공개 패키지에 포함하지 않았다. USB 자동 감시 기능을 설치했다는 의미는 아니다.

21:29~21:30 KST에 공식 기업 발급·재발급 화면의 1단계 `약관동의 및 사용자 본인확인`에 진입했다. 사이트가 인증 프로그램 설치를 요구하여 안내의 확인 버튼으로 공식 설치 페이지에 이동했다. 필수 인증 프로그램은 WizIn-Delfino G3로 표시되었고, 통합 보안프로그램은 OTP 이용 시 선택 설치가 가능하다고 안내했다. 21:33 KST에 공식 버튼으로 `delfino-g3.exe`를 다운로드하고 파일 열기를 실행했다. 21:34 KST에 설치 프로그램 `Delfino G3 (x86) 3.7.1.0`과 확인된 게시자 `WIZVERA Co., Ltd.`를 확인해 요청된 설치를 진행했고, 관리자 암호 입력은 요구되지 않았다. 설치 프로그램 종료 후에도 사이트가 설치 안내를 표시했다.

21:36 KST에 Edge의 `obank.kbstar.com` 사이트 정보에서 `디바이스의 앱`이 자동 차단되어 있음을 확인했다. 요청된 인증 프로그램 연결을 위해 해당 도메인의 권한을 허용하고 새로고침했다. 21:37 KST에는 설치 요구 안내가 사라졌고 발급·재발급 1단계가 유지됐다. 이는 초기 프로그램 감지 문제의 해소를 관찰한 것이며 모든 인증 기능의 ARM·Parallels 호환을 검증한 것은 아니다. 다른 사이트·전역 보안 설정은 변경하지 않았다.

현재 발급 1단계에 필수 약관 5개의 선택 상태를 확인했다. 사용자 ID·사업자등록번호·개인사업자의 주민번호 입력 폼을 준비했으며 실제 값을 입력하거나 본인확인 요청을 제출하지 않았다. 다음 진행은 당사자가 이 공식 화면에서 본인확인 정보를 입력하고 `약관 동의/본인확인`을 수행한 뒤 새 결과 화면을 확인하는 것이다. 수수료 상품·발급·USB 저장은 아직 미실행이다.

v0.2.0 생성·조회 회귀 11개(생성 4개, 에이전트 조회 7개)가 통과했다. 실제 설치·연동 관찰을 guide에 추가한 뒤 생성 일치 검사 4개를 다시 통과했다. 최종 원본·생성 번들·로컬 설치 guide·실행 중 MCP의 guide가 일치한다. 로컬 이전 v0.1.1은 임시 검증 디렉터리에 보존했다. MCP의 새 버전 실행 증거 수치는 모두 0으로 유지되어 실제 화면 관찰을 자동 재생 성공으로 기록하지 않았다.

## KB 개인사업자 ID 조회와 채팅 입력 카드

21:41 KST에 실제 ID 조회 팝업의 개인사업자 선택과 고객명·생년월일(YYMMDD)·출금계좌번호·계좌 비밀번호 행을 확인했다. 계좌정보는 아직 입력하지 않았고 조회 확인도 제출하지 않았다. 사용자가 iPhone을 가지고 외출하므로 미러링과 KB기업뱅킹 계좌 확인은 보류했다. 복귀 후 현재 화면·세션을 다시 확인한다.

v0.2.1 플레이북은 미등록 KB 고객명·출금계좌번호만 전용 카드로 받는 절차와 기존 생년월일 재사용, 개인사업자 ID 조회 전용 입력 경로를 추가했다. 원본·생성 번들·로컬 설치본을 동기화했다. 앞 버전 v0.2.0은 임시 검증 폴더에 보존했다.

코드에는 은행별 키체인 프로필, 설정 편집, 뽀미 Mac 채팅의 일반 질문 카드와 별도 은행정보 카드, 일회용 네이티브 제출 요청을 구현했다. 일반 질문 답은 모델로 전달되고 은행 원문은 로컬 저장 경로에만 전달된다. 등록 여부만 반환하며 취소·만료·세션 종료 뒤 제출과 기존 항목 덮어쓰기를 차단한다. 비밀번호·OTP·전체 주민번호는 저장하지 않는다.

`kb_id_lookup` 어댑터는 정확한 KB 공식 호스트·경로·페이지, 개인사업자 행·생년월일 예시, 입력 위치·포커스를 검증한다. 독립 리뷰에서 보호 라벨의 대소문자·콜론·별표 변형 누락을 찾아 정규화와 회귀를 보완했다. KB 입력·기존 세움터 입력 회귀 32개를 포함해 프로필·네이티브·카탈로그 관련 Swift 81개가 통과했다. 카탈로그 생성 4개와 에이전트 조회 7개도 통과했다. 테스트의 은행정보는 합성값이며 실제 프로필 키체인을 변경하지 않았다.

추가로 질문 카드 관련 TypeScript 회귀 43개, 브라우저 종료 회귀 2개, TypeScript 검사와 Mac 번들의 WKWebView 기동 검사 1개가 통과했다. 실제 Chrome 합성 fixture에서 선택·직접 입력·제출·취소와 은행 카드의 미등록 항목만 표시, 제출 뒤 입력 제거를 확인했다. 360px 영역에서 가로 넘침이 없었다. Mac 번들만 갱신했으며 Android 설치본은 변경하지 않았다.

21:55 KST에 기존 앱과 같은 Apple Development 서명으로 빌드·서명 검증한 앱을 설치하고, 대화 시작 전 대기 중이던 GUI를 재시작했다. 설치본에 채팅·음성 전환과 입력창이 표시되는 것을 확인했다. 새 MCP에서 KB 어댑터 스키마를 확인하고 `profile_status`로 기존 6개 기본정보의 등록 상태가 보존되며 은행 프로필은 미등록임을 확인했다. 기존 앱은 임시 검증 폴더에 백업했다. 실제 계좌 원문을 조회하거나 저장하지 않았다.

실제 은행정보 카드 저장, KB ID 조회·본인확인, 인증서 발급·재발급·USB 복사는 여전히 미검증이다. 카드 제출 성공·입력 검증과 실제 은행 업무 성공을 구분한다.

## 23:16 KST 재개: KB 생년월일 실제 입력

사용자가 진행을 요청해 폰 콤보를 호출했으나 iPhone이 잠금 해제 상태여서 미러링 연결이 차단됐다. 아이폰 잠금·Mac 근처 배치를 한 번 요청하고 폰 도구 재시도는 하지 않았다. Windows KB 발급 화면의 기존 필수 약관 선택과 빈 입력 폼을 확인했다. ID 조회 팝업을 다시 열고 개인사업자를 선택했다. 팝업에 다시 표시된 로컬 앱 접근 요청은 Escape로 닫았으며 새 권한을 부여하지 않았다.

새 서명 런타임의 `profile_fill(form: kb_id_lookup, bank_id: kb, field: birth_date)`로 저장된 생년월일을 실제 개인사업자 입력칸에 전달했고, 로컬 검증에서 `verified: true`를 반환했다. 원문은 도구 응답·문서에 포함하지 않았고 입력 후 일반 화면 캡처를 하지 않았다. 고객명·계좌번호는 아직 미입력이며 비밀번호·ID 조회 확인도 수행하지 않았다. 폰 연결 이후 KB기업뱅킹의 해당 사업자 계좌 확인부터 재개한다.
