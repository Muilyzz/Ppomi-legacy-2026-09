# 에이전트 대화창과 작업 화면

2026-09-09부터 Mac의 일반 실행과 Dock 재열기는 뽀미 자체 대화를 기본으로 연다. Android와 같은 번들 React 대화 껍데기를 신뢰된 로컬 WebView에 표시한다. 채팅과 음성은 같은 헤더·탭·도구 내역·질문 카드·입력 자리를 쓰며, 음성은 말풍선 자리에 상태, 입력창 자리에 시작·음소거를 둔다. 입력창이 창 안에 유지되도록 높이를 채운다. 질문 카드는 두 플랫폼 공통이고, 은행정보 카드는 기기에서 은행 프로필을 지원할 때만 연다. 음성 호출 설정을 끄는 동작과 현재 대화 종료는 분리한다. 이 기본 진입에서는 외부 ChatGPT/Codex 창을 자동 배치하지 않는다.

아래 작업대 구조는 메뉴의 기록·기기 제어와 명시적 키오스크 진입에서 계속 사용한다. `state.reveal()`의 제어·기록 의미를 유지하고, 일반 대화 진입은 별도 `openChat()`으로 전달한다. Mac의 안내 예시는 실제 제공되는 플레이북 조회이며 Android 앱 제어 기능을 Mac에도 제공한다고 표시하지 않는다.


뽀미 작업대는 상단 기록과 하단 두 열로 구성한다. 상단은 기록 요약을 기본으로 표시하며, 펼치면 타임라인·증빙·전표·절차·몸과 생활의 전체 기록 화면을 보여 준다. 하단 왼쪽은 설치된 ChatGPT 또는 Codex의 실제 macOS 대화창, 하단 오른쪽은 선택한 iPhone 미러링·Android 미러링 또는 Parallels의 Windows 창이다. 기록을 펼쳐도 두 열의 역할은 유지한다. 승인 버튼은 대화 영역 하단에 고정한다.

이 기능은 외부 창의 크기·위치·순서를 함께 관리한다. 대화 내용 복제, 웹뷰 로그인, 채팅 전송, MCP 등록이나 연결 성공 판정을 하지 않는다. MCP 서버 설정은 해당 에이전트의 설정을 따르며, 창이 보인다는 사실은 도구가 연결됐다는 뜻이 아니다.

제어 선택기는 **iPhone / Android / Windows** 순서다. Android는 선택하거나 다시 배치할 때 로컬 에뮬레이터·보조 앱을 준비하고 `Ppomi Android` scrcpy 창을 붙인다. 준비 중·실패 상태를 하단에 표시한다. 보조 앱의 접근성 제어와 미러링은 별개이며, `android_status`로 실제 서비스 연결을 확인한다. [Android 제어와 테스트](android-control.md)에 실행 경로와 범위를 정리한다.

외부 앱은 설치 번들의 식별자와 실행 파일로 확인한다. 앱 이름만으로 구분하지 않으며 여러 대화창이 있을 때는 확인된 한 창을 계속 사용한다. 연결 후 일반 클릭·스크롤·타이머 조회는 대화창을 활성화하거나 원래 위치로 계속 끌어오지 않는다. 사용자가 다시 배치하거나 창 모드·디스플레이·기록 펼침 상태·제어 대상이 바뀔 때 크기를 맞추고, 이후에는 실제 창이 안정된 크기를 읽어 배치한다. 외부 제어창을 직접 옮겨도 기록이나 대화가 다른 열로 이동하지 않는다.

iPhone은 미러링 앱의 **보기 → 작게** 메뉴를 한 번 요청한다. 메뉴가 없거나 비활성 상태면 실제 창 크기를 그대로 사용한다. 2026-09-08 점검 시에는 iPhone을 사용할 수 없어 이 메뉴가 비활성 상태였으며, 연결된 iPhone의 실제 축소 동작은 별도 확인이 필요하다. Windows는 현재 네이티브 창의 비율을 보존하여 제어 영역 안으로 축소한다. 이미 작은 창은 확대하지 않으며, Parallels의 화면 속 화면(PiP) 모드로 강제 전환하지 않는다.

기록 영역의 높이는 하단 작업 공간과 제어창의 실제 크기를 고려해 정한다. 외부 앱이 허용하는 최소 크기를 수용할 수 없으면 다른 영역이나 승인 버튼을 가리지 않도록 배치를 중단하고 안내한다. 기록 요약·전체 보기 전환과 기록 탭 이동은 대화 앱 선택, 기록 페이지의 선택과 스크롤 상태를 유지한다. 뽀미 작업창을 닫거나 앱을 정상 종료하면 연결한 대화창의 원래 크기·위치·최소화 상태를 복원한다.

키오스크도 상단 기록·하단 대화/제어 구조를 사용한다. 실제 외부 창의 자리를 제외한 영역을 덮고, 기존 기록 뷰·대화 도구막대·제어 선택기·승인 컨트롤을 각 덮개에 옮긴다. 일반 창으로 돌아오면 같은 뷰를 다시 사용한다. 기존 아무 키로 나가기 버튼 표시·두 번째 Escape로 종료 동작을 유지한다.

기하·창 선택·입력 포커스·기록 페이지 유지의 자동 검증 범위와 뷰 소유 원칙은 [UI 구조](ui-structure.md)에 정리한다. 실제 앱의 최소 크기, 접근성 권한, Stage Manager/Spaces의 창 순서와 키오스크 복귀는 잠금 해제된 Mac에서 별도 확인해야 한다.

## Windows 창을 움직이는 손

작업 화면이 Parallels의 Windows 창이면 MCP 도구 `windows_screen`(OCR) · `windows_click` · `windows_type` · `windows_key` · `windows_scroll` · `windows_open`이 iPhone의 `phone_*`와 같은 역할을 한다. 구현은 같은 `phone` CLI의 `--windows` 모드다: 창은 실행 중인 `com.parallels.*` 프로세스의 창 가운데 VM 이름(`prl_vm_app --vm-name …`)과 제목이 같은 것(없으면 가장 큰 것)이며, App Store 판에서는 이 창을 호스트 프로세스 `prl_client_app`이 가진다. 입력은 클립보드 붙여넣기(Ctrl+V), 열기는 Win+R, 스크롤은 휠 노치이고, 클릭·휠 전에 포인터를 창 왼쪽 밖에서 안으로 들여보낸다(Parallels는 상대 이동으로 게스트 포인터를 옮긴다). 수식키는 실제 키처럼 누르고 뗀다(플래그만 주면 게스트에 Win 키가 눌린 채 남는다). 클릭 지점 위에 다른 창(에이전트 대화창 등)이 있으면 클릭하지 않고 실패로 알린다.

전제: Windows는 창 모드(전체 화면·Coherence 아님), Parallels 구성 › 하드웨어 › 마우스 및 키보드 › 마우스는 “게임용 자동 감지”(SmartMouse 켜짐). 꺼져 있으면 키보드·클립보드는 통하지만 클릭이 게스트 포인터를 따라가지 않는다(2026-09-07 이 Mac의 VM이 그랬다). 켠 뒤에는 VM 뷰가 활성화 직후의 첫 클릭을 포커스용으로 삼키므로, 실제 클릭 전에 창 제목줄을 한 번 누른다. 2026-09-07 캡처·OCR·키·붙여넣기·Win+R·휠·클릭(등기소 홈의 부동산/법인 탭 전환)을 실제 VM에서 확인했다.
