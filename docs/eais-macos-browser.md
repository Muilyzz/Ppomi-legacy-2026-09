# 세움터 macOS Chrome 확인 기록

확인일: 2026-09-08. 공개 화면·프로그램 메타데이터만 기록하며 계정·비밀번호·주민번호·실제 소유자·대상 부동산·문서 내용은 포함하지 않는다.

## 현재 확인된 경로

| 단계 | 관찰 | 의미와 한계 |
|---|---|---|
| 홈페이지 | Chrome에서 `https://www.eais.go.kr/`를 열고 DOM을 읽음 | Mac Chrome에서 일반 화면을 탐색할 수 있음 |
| 현황도 안내 | 홈 `건축물현황도 발급` → `https://www.eais.go.kr/moct/bci/aaa03/BCIAAA03L02` | 배치도·본인소유 평면도·그 밖의 증빙과 승인 안내 확인 |
| 본인소유 평면도 | 개인·법인 구분과 주민(법인)등록번호 필드 표시 | 실제 값 입력이나 소유 조회 완료는 하지 않음 |
| 다른 신청 경로 | 다른 소유자의 경우 증빙·지자체 승인, 다중이용 건축물 관련 신청서·승인 안내 | 신청 제출·승인 결과를 확인한 것은 아님 |

| 회원·비회원 선택 | 비인증 상태의 현황도 직접 진입에서 `/moct/bci/aza01/BCIAZA01F02?returnUrl=%2Fbci%2FBCIAAA03L02`로 이동 | 발급서비스 회원·비회원 선택 화면 확인 |
| 회원 발급 로그인 | 선택 화면의 `로그인 하기` → `/moct/awp/abb01/AWPABB01F01` | 아래 인증서 모듈 알림으로 입력 폼 준비까지 진행하지 못함 |

| 모듈 알림과 다운로드 | `인증서 관리 모듈이 설치되지 않았습니다.` 이후 확인·닫기 시 `/kcase/exe/KSignCASE_For_HTML5_Windows_v1.3.29.exe`로 이동, `ERR_BLOCKED_BY_CLIENT` 표시 | Windows 실행 파일 경로이며 다운로드 차단 우회를 하지 않음. 브라우저 뒤로 가기는 회원·비회원 선택 화면으로 돌아옴 |

| 회원가입 준비 | Mac Chrome 홈 `회원가입`에서 일반·사업자·외국인 유형 확인. `일반회원 가입하기` → `/moct/awp/aba01/AWPABA01F02` 약관 동의 화면에 도달 | 일반회원 유형·약관 화면 준비를 실기로 확인. 기록한 약관 경로에는 세션 값이 없음 |
| 가입 단계 안내 | 유형선택 → 약관동의 → 본인인증 → 정보입력 → 가입완료의 5단계 표시 | 안내된 순서이며 본인인증·정보입력 화면에는 아직 진입하지 않음 |
| 약관 동의 상태 | 필수 이용약관·필수 개인정보 수집·선택 개인정보 수집 체크박스 3개 모두 선택하지 않음 | 다음 버튼을 누르지 않았고 동의·본인 인증·가입을 완료하지 않음 |

회원가입 준비는 일반회원 유형 선택과 약관 화면까지 확인했다. 약관 동의 이후의 본인인증·정보입력 화면, 비회원 개인정보 폼, 가입 완료·로그인·신청 제출·도면 발급 완료는 아직 검증하지 않았다. 두 회원 로그인 진입점과 비회원 진입에서 막힌 사실은 기록하되 정부 사이트라는 분류만으로 Windows가 필수라고 결론 내리지 않는다. Mac Chrome에서 관찰된 단계와 특정 인증·출력 구성 요소의 호환성은 별도로 확인한다. 일반 메뉴의 아직 확인하지 않은 공식 경로는 탐색하되 같은 모듈 경고·차단된 다운로드를 반복하거나 차단을 우회하지 않는다.

초기 Parallels 확인에서는 CUA 입력에서 URL의 영문이 누락되고 기호만 Bing 검색으로 전달되었다. 해당 경로의 직접 키 입력과 클립보드 붙여넣기도 의도한 문자열의 도착을 확인하지 못했다. 이 관찰은 당시 CUA 게스트 입력 경로의 문제이며 Windows 전체의 조작 불가나 EAIS 호환성 실패로 확대하지 않는다.

이후 최신 설치본의 Ppomi MCP에 직접 stdio로 연결하여 Windows 입력 경로를 다시 확인했다.

| 단계 | 추가 관찰 | 의미와 한계 |
|---|---|---|
| Windows 화면 수집 | `windows_screen`으로 Parallels의 Windows 11 화면과 OCR을 읽음 | 화면 읽기 성공이며 사이트 인증·문서 수집 성공은 아님 |
| Windows 사이트 열기 | `windows_open`으로 EAIS 홈페이지를 열고 게스트 Edge에서 표시를 확인 | Ppomi의 URL 열기 경로는 성공. 초기 CUA 입력 결과와 구분 |
| 키 전달 | `windows_key`의 `ctrl+l`로 Edge 주소창 선택을 확인 | 게스트에 키가 전달됨을 확인. 모든 입력·클릭의 정상 동작을 뜻하지 않음 |
| 홈페이지 로그인 | `로그인` 클릭 후 버튼에 포커스 테두리가 생기지만 로그인 화면으로 이동하지 않음 | 클릭 후 관찰 상태이며 인증 성공이나 전체 입력 실패로 판정하지 않음 |
| 기존 로그인 경로 | 관찰된 `/moct/awp/abb01/AWPABB01F01`을 직접 열었을 때 빈 화면 표시 | 해당 직접 진입 결과만 확인. 새 로그인 경로나 세션 URL을 추측하지 않음 |
| 브라우저 오류 | Edge 개발자 도구 Console에서 `Uncaught (in promise) TypeError: window.anyidAdaptor.ssoLoginPage is not a function` 확인. 표시된 스크립트는 `bac6c11.js` | 실제 관찰된 오류. 입력 드라이버·사이트 배포·인증 연동 중 최종 원인을 이 문구만으로 단정하지 않음 |
| 새로 읽기 후 진입 | `Ctrl+Shift+R`로 페이지를 새로 읽은 뒤 기존 빈 화면을 벗어나 새 `/moct/awp/abb01/AWPABB01F11` 정부 통합인증 페이지로 이동 | TypeError·빈 화면 이후 이 경로로 회복한 정황. 캐시만이 원인이었다고 확정하지 않으며 새 세션 URL·`tx` 값은 저장하지 않음 |
| Windows 브라우저 권한 | 사용자가 세움터의 로컬 인증 프로그램 접근을 승인했고, 후속 실행에서 `허용` 적용 후 사이트 정보의 `디바이스의 앱` 토글 켜짐을 확인함 | 사용자 승인과 브라우저 권한 반영을 모두 검증. 같은 권한을 다시 묻지 않음 |
| 인증 프로그램 상태 | `인증서 관리 모듈이 설치되지 않았습니다.` JavaScript 알림과 보안 프로그램 모듈 로딩 화면 표시 | 로그인 화면의 인증 구성 요소 단계에 도달했으나 인증 성공은 아님 |
| 로컬 연결 오류 | Console에서 AnyID 어댑터 초기화·모든 스크립트 로드 완료·AnyID 모듈 로드 로그 이후 `wss://127.0.0.1:8443` 연결의 `ERR_CONNECTION_REFUSED` 확인 | 권한 반영 확인 전의 관찰이며 현재 권한 상태와 구분. 후속 권한 반영만으로 로컬 모듈 연결까지 성공했다고 판정하지 않음 |

Windows에서 홈페이지 탐색·키 전달과 새 통합인증 페이지 진입은 확인했으나 로그인·본인 인증·신청·도면 수집은 완료하지 않았다. 로컬 인증 프로그램 접근 권한은 후속 실행에서 사용자 승인과 브라우저 반영을 모두 확인했다. 같은 권한을 중복 질문하지 않는다. TypeError·빈 화면에서 새로 읽기를 통해 다음 화면으로 진행한 결과는 남기되, 같은 실패를 근거 없이 반복하지 않는다. 이후 공식 설치 파일 실행·설치 완료와 공동인증서 전자서명 창 진입까지 확인했으며, 상세 상태는 아래 후속 기록에 남겼다.

### 후속 Windows 응답 진단

뽀미 콘솔 창 닫기 호출이 성공한 뒤에도 Windows의 접근 권한 `허용`, 알림 `확인`, Enter와 시작 버튼에서 기대한 반응을 확인하지 못했다. CUA와 Ppomi MCP 양쪽에서 게스트 작업표시줄 시계가 16:23에 머무른 화면을 관찰했으며, 당시 Mac 시각은 16:29 이후였다. 이후 게스트 시계가 16:32로 한 번 갱신되었으므로 영구적인 OS 정지로 판정하지 않는다. Parallels의 macOS 작업 메뉴는 정상적으로 반응했다. 긴 무반응과 화면 갱신 지연을 관찰했지만 게스트 OS·화면 렌더링·입력 전달 중 원인을 구분하지 못했고, 뽀미의 창 배치가 원인인지도 확정하지 않았다. 해당 시점의 무반응을 사이트나 입력 드라이버만의 문제로 단정하지 않는다.

Parallels UI에서 일시중지 오버레이와 재개를 확인했지만 화면·입력의 회복은 확인하지 못했다. 설치 번들의 공식 `prlctl list --all --name 'Windows 11' --output name,status`는 `running`을 반환했다. 이 상태는 VM 실행 상태이며 게스트 UI가 정상 응답한다는 증거가 아니다. `status`와 게스트 시간 읽기를 위한 `exec`는 Pro·Business 에디션 전용이라는 오류로 거절되어 게스트 내부 응답을 검증하지 못했다. 라이선스 제한을 우회하지 않았다.

사용자의 Windows 재시작 승인을 받은 뒤 Parallels의 `작업 → 다시 시작`과 확인 창의 `예`로 정상 재시작을 요청했다. 강제 재설정은 하지 않았다. 검은 부팅 화면과 `100% 완료됨 컴퓨터를 계속 켜 두세요.` 화면을 거쳐 Windows 바탕화면 복귀를 확인했으며, 작업표시줄 시계가 16:35에서 16:36으로 갱신되는 것도 확인했다.

재시작 후 Ppomi MCP의 첫 시작 버튼 좌표 클릭에서는 메뉴가 열리지 않았지만, 이어 CUA로 같은 시작 버튼을 직접 클릭했을 때 실제 시작 메뉴가 열렸다. 이후 `windows_open`으로 Edge 초기 설정 화면에 도달했다. 이는 EAIS 재접속 성공이 아니다. 초기 설정의 `데이터 없이 시작` 클릭에서는 다시 기대한 화면 전환을 확인하지 못했으므로 입력 경로가 완전히 회복되었다고 판단하지 않는다. Ppomi의 초기 포커스 처리 등 입력 경로별 차이도 추가 확인이 필요하다.

재시작 직후에는 세움터 로컬 프로그램 접근의 사용자 승인만 받았고 브라우저 반영은 미검증이었다. 이후 권한 반영을 직접 확인한 결과는 아래에 기록했다. 사용자가 요청한 VLM 화면 인식 구현 작업을 병행했으며, 세움터 로그인·본인 인증·신청·도면 수집은 여전히 미완료다.

### 후속 Ppomi 클릭 전후 검증

Parallels 설정 창을 닫고 뽀미 GUI를 `숨기기` 메뉴로 숨긴 상태에서, Ppomi MCP의 `windows_click` 한 번을 기준으로 공식 `prl_perf_ctl -s hidhook` 카운터를 직전·직후에 읽었다. 이 비교에서는 다음 변화를 확인했다.

| 카운터 | 클릭 전 | 클릭 후 | 변화량 |
|---|---:|---:|---:|
| `mouse.injected` | 3060 | 3082 | +22 |
| `mouse.processed` | 648 | 664 | +16 |
| `mouse.sent` | 648 | 664 | +16 |
| 키보드 카운터 | — | — | 변화 없음 |

직후 새 스크린샷에서 Windows 시작 메뉴가 실제로 열린 것도 확인했다. 이 결과는 Ppomi 클릭 한 번의 전후를 동기화한 전송·화면 변화 증거이며, 앞서 CUA 클릭을 포함한 관찰 구간에서 마우스 카운터가 증가하지 않았던 결과와 입력 경로를 구분한다.

이때 마우스와 키보드 설정은 모두 `게임용 자동 감지`를 유지했다. 강제 게임 최적화 모드를 선택하려던 UI 조작은 반영을 확인하지 못했고 설정도 바뀌지 않았으므로, 이번 성공을 강제 게임 모드의 효과로 기록하지 않는다. 뽀미 숨김·설정 창 닫힘과 성공의 동시 관찰만으로 이전 무반응의 원인을 확정하지도 않는다. 연속 Ppomi 동작 검증과 세움터 재개를 진행 중이며, 사이트 인증·도면 수집 완료를 확인한 것은 아니다.

후속 Ppomi MCP 동작에서도 두 번째 시작 버튼 클릭으로 시작 메뉴가 닫히는 것을 확인했다. Edge 초기 설정에서는 선택적 제공을 거부하는 `허용 안 함` 라디오의 실제 선택과, 이어 `확인 후 계속` 클릭으로 다음 초기 설정 페이지에 진입하는 것을 확인했다. 이 후속 구간에서는 CUA로 화면을 관찰하고 Ppomi MCP로 동작을 수행했다.

Mac 잠금은 해제되어 있으며, 최신 설치본의 `screen_inspect`를 개인정보 없는 실제 Edge 초기 설정 화면에 호출하는 실기도 성공했다. VLM은 파란 영역을 선택된 라디오로 오인하지 않고 텍스트 드래그 선택으로 설명했으며, 양쪽 라디오가 비어 있고 계속 버튼이 비활성인 상태를 원본 화면과 맞게 구분했다. 반환 상태는 `uncertain`, 좌표 후보는 `null`이었고 실제 사용량은 입력 2162·출력 130토큰이다. 이는 이 화면 한 건의 관찰 결과이며 일반적인 정확도 보장이나 자동 클릭 성공을 뜻하지 않는다.

이 관찰 당시에는 Microsoft의 선택적 개인화 데이터 제공을 거부하는 Edge 초기 설정 페이지를 처리 중이었다. 이후 초기 설정 완료·세움터 재진입·로컬 접근 권한 반영은 다음 절에 기록했으며, 인증·신청·도면 수집은 아직 완료하지 않았다.

### Edge 초기 설정 완료와 세움터 접근 권한 반영

이후 Edge 초기 설정을 선택적 데이터 제공 거부로 마쳤고, 세움터 홈페이지와 새 로그인 화면에 다시 진입했다. 겹쳐 표시된 모듈 미설치 JavaScript 경고를 Ppomi MCP로 확인한 뒤, 공식 `KSignCASE_For_HTML5_Windows_v1.3.29.exe` 다운로드가 완료되고 `파일 열기`가 표시되는 것을 확인했다. 이는 공식 설치 파일 취득 결과이며 모듈 설치·실행이나 인증 성공을 뜻하지 않는다.

앞서 사용자 승인을 받은 로컬 프로그램 접근의 `허용`을 클릭하고, Edge 사이트 정보에서 `디바이스의 앱` 토글이 켜진 것을 직접 확인했다. 이 권한은 이제 사용자 승인과 브라우저 반영을 모두 검증했으므로 같은 권한을 다시 요청하지 않는다. 권한 반영 이전의 연결 실패·무반응 기록은 당시 관찰로 유지하며 현재 권한 상태와 구분한다.

뽀미 콘솔을 다시 연 뒤에도 Ppomi MCP 클릭으로 Windows 시작 메뉴가 실제로 열리는 것을 확인했다. 마우스 게임 옵션은 계속 `게임용 자동 감지`이며, GUI가 열려 있다는 사실만으로 이전 입력 실패의 원인을 확정하지 않는다. 이 시점에는 다운로드한 설치 파일 열기를 준비했으며, 이후 설치 결과는 다음 절에 기록했다. 세움터 인증·로그인·신청·도면 수집 성공은 아직 확인하지 않았다. 새 인증 세션 URL과 계정 값은 기록하지 않는다.

### KSign 설치 완료와 공동인증서 사용자 단계

Windows Edge에서 공식 다운로드 파일 `KSignCASE_For_HTML5_Windows_v1.3.29.exe`를 실행했다. 사용자가 KSign 설치와 UAC 승인을 명시적으로 허용한 뒤 진행했으며, `KCaseAgentforHTML5 1.3.29.0` 설치 완료 화면을 확인했다. 완료 화면을 닫고 세움터를 새로 읽은 뒤 공동인증서 전자서명 창이 정상적으로 열렸다. 창에는 모듈 버전 `v1.3.29`, 암호 모듈 버전 `v2.5.1.1`이 표시되었다. 이는 Windows의 설치 완료와 인증서 창 진입 증거이며, Mac용 모듈 지원이나 로그인 성공 증거는 아니다.

하드디스크 저장소의 인증서 목록은 비어 있었다. 이 목록만으로 USB 등 다른 저장소에도 인증서가 없다고 판단하지 않는다. 당시 Windows 또는 USB 인증서 준비와 직접 선택·암호 입력·로그인을 요청했으나, 이후 사용자가 간편인증의 통신사PASS를 선택하여 그 요청은 대체되었다. 공동인증서 선택·암호 입력·로그인 완료는 확인하지 않았다. 인증서 내용·암호·계정 정보·인증 세션 URL은 기록하지 않는다.

이 구간에서 `게임용 자동 감지` 모드를 유지한 채 여러 Ppomi MCP 클릭의 실제 화면 전환을 확인했다. 다만 UAC의 최초 승인 클릭에서는 변화가 없었고, 화면을 다시 관찰한 뒤 두 번째 클릭에서 다음 단계로 진행했다. 여러 동작의 성공과 남은 재시도 사례를 함께 기록하며, 입력 경로가 완전히 해결되었다거나 특정 설정이 원인이었다고 결론 내리지 않는다.

### 현재 단계: 간편인증의 통신사PASS 선택 완료

사용자가 금융인증서를 요청하여 공동인증서 창을 닫고 로그인 방법을 다시 확인했다. [Any-ID 공식 개인 이용방법](https://www.anyid.go.kr/rprssite/utztnmthd?type=idv)은 정부 통합로그인 사용 토글과 금융인증서를 포함한 인증수단을 안내하지만, 이번 세움터 화면에서 금융인증서 선택 경로는 확인하지 못했다. Any-ID 전체의 지원 안내를 세움터 현재 화면의 금융인증서 제공 증거로 해석하지 않는다. 금융인증서·공동인증서·은행의 민간 간편인증도 구분한다.

이후 사용자가 간편인증과 `통신사PASS`를 명시적으로 선택했다. 간편인증 창의 빨간 PASS 아이콘을 클릭한 뒤 `통신사PASS` 헤더, 선택 테두리와 통신사 필드가 표시된 것을 확인했다. `삼성패스`는 별도 제공자이며 이번 선택은 통신사PASS다.

간편인증 창을 두 번 열었을 때 제공자 순서가 서로 달랐다. 따라서 제공자 위치·순번·좌표를 다음 실행에 고정하지 않는다. 이번 관찰에서는 OCR 텍스트 위치 클릭만으로 선택 변화가 없었으며, 최신 화면에서 확인한 빨간 PASS 아이콘 중앙 클릭 후 선택이 반영되었다. 재사용할 때는 현재 화면의 실제 아이콘·라벨을 다시 찾고 클릭 후 헤더와 선택 테두리로 제공자를 검증한다.

이 관찰 시점의 이름·생년월일·통신사·휴대폰 필드는 모두 미입력이고, 약관은 미동의이며 인증요청은 전송하지 않았다. 이후 [자동입력 기본정보 프로필](identity-profiles.md)을 추가하여, 이번 당사자가 등록하고 사용을 허용한 프로필의 네 항목은 `profile_fill`의 `eais_pass` 양식으로 준비할 수 있게 했다. 아직 없는 정보는 대화나 설정에서 등록할 수 있으며, 대화 기록에 남기고 싶지 않으면 앱에서 직접 등록한다. 입력 원문을 도구 응답으로 읽어 전달하지 않고 최신 라벨·입력칸 위치를 검증해 한 항목씩 입력한다. 후속 실기에서는 실제 MCP 저장과 설치본의 단건 조회, 통신사 선택 반영을 확인했다. 이름·생년월일·휴대폰 입력은 아직 완료하지 못했으며, 요청한 입력칸 포커스나 입력 결과를 확인하지 못하면 값을 재전송하지 않고 중단했다. 프로필 목록의 macOS Keychain 조회 오류도 발견해 계정별 읽기로 수정했고, 서명된 별도 실행 파일에서 목록 조회 성공을 확인했다. 최종 설치본의 MCP 전체 목록 조회와 설정의 마스킹 목록 표시는 확인했다. 나머지 PASS 텍스트 입력은 아직 미완료다.

약관 내용 확인과 동의, 인증요청 및 휴대폰 PASS 인증은 당사자가 직접 처리한다. 이전 공동인증서 파일 준비 요청은 더 이상 현재 대기 단계가 아니다. 사용자 완료 후 최신 화면에서 인증·로그인 결과를 확인하고 도면 작업을 이어간다. 인증·로그인·신청·도면 수집은 아직 미완료이며 실제 입력값은 기록하지 않는다.

## 이 Mac의 설치 메타데이터

Mac CPU 아키텍처는 `arm64`다. 설치 메타데이터 조사에서는 설치 영수증·앱·LaunchAgent/Daemon 이름과 바이너리 메타데이터만 읽었고, 해당 모듈의 설치·실행·재시작은 하지 않았다.

|---|---|---|
| CrossEX | 패키지 영수증 1.0.1.9, CrossEXService 실행 파일, LaunchAgent 존재. x86_64, Iniline 개발자 서명 메타데이터 | EAIS·Chrome 연동 성공은 미확인 |

`npraontouchenex.plugin` 이름의 심볼릭 링크는 대상이 없어 작동하는 설치 모듈로 세지 않았다. 개발자 서명 표시는 메타데이터 확인이며 전체 무결성·사이트 호환성 검사 결과가 아니다.

[KSignCASE 제조사 공식 안내](https://www.ksign.com/ksign/solution/ksignCASE.php)는 제품 차원에서 Mac을 포함한 운영체제 지원을 안내한다. 다만 EAIS용 Mac 설치 프로그램의 공식 배포는 확인하지 못했다. 제조사의 제품 지원 범위와 EAIS의 실제 배포·연동 상태는 구분한다.

## 가족이 재사용하는 절차의 범위

공개 패키지는 `Ppomi/Sources/Ppomi/Catalog/eais/`다. 회원가입 준비, 로그인 준비, 현황도 발급 준비의 명세와 사람이 개입하는 지점을 제공한다. 일반 안내·메뉴·폼 준비를 자동으로 이어가고, 이미 제공되었으며 이 사이트 사용이 허용된 이름·연락처·주소 등 일반 가입·신청 정보는 현재 작업 범위에서 자동 입력한다. 필요한 정보가 없을 때만 질문하며 실제 값은 공개 패키지·발자국에 저장하지 않는다. 자격 증명·비밀번호·인증서 암호·인증용 주민번호·OTP·생체 인증·CAPTCHA·새 동의·새 민감 접근 권한이 필요한 실제 지점만 당사자에게 넘긴다. 사용자가 완료하면 갱신한 화면으로 상태를 확인하고 원래 작업을 재개한다.

통신사PASS의 이름·생년월일·휴대폰·통신사는 가족별 키체인 프로필에 등록한 항목을 전용 `profile_fill` 경로로 입력할 수 있다. 기본 `self`와 다른 가족의 프로필 ID를 구분한다. 최신 세움터 주소·통신사PASS 헤더·항목 라벨과 좌표를 검증하며, 휴대폰은 010 뒤 입력칸과 통신사 드롭다운을 구분한다. 약관 동의·인증요청·휴대폰 승인은 자동입력 범위에 포함하지 않는다.

계정·인증·소유 권한은 세션의 당사자별로 분리한다. 다른 가족의 계정을 이어 쓰거나 이전 작업의 인증값·소유 정보를 다음 작업의 기본값으로 만들지 않는다. 약관은 필수·선택을 구분하며 선택 개인정보 수집·마케팅은 자동 동의하지 않는다. 이미 세션에서 제공된 일반 작업 의사·입력은 다시 묻지 않는다.

명세 단계는 실제 자동 실행 코드나 성공 증거가 아니다. 현재 관찰된 문구와 URL만 기록했으며 가입·로그인 이후의 노드 ID·CSS 선택자·버튼명은 추측해 추가하지 않았다. 후속 확인에서는 `행동 전 일반 화면 → 수행한 일반 탐색 → 관찰된 상태 → 필요한 사용자 단계 → 재개 후 결과`를 민감정보 없이 남긴다. 신청 접수·승인 대기·발급 완료도 구분한다.

## 뽀미 반영과 검증

웹 실행 대상(`launch.target: browser`), `browser_open`, 세움터·등기소 가입/로그인 준비 명세를 반영했다. 관련 Swift 테스트 24개와 허브 테스트 28개가 통과했다. 기존 개발 서명 요구사항을 유지해 로컬 앱을 교체했고, 설치본의 MCP에서 두 웹 명세·상세 가이드·가족 공통 규칙을 읽는 것을 확인했다. 이후 Mac 잠금 해제와 뽀미 창 열림을 확인했다. 세움터 카드의 Chrome 열기 버튼은 아직 실제 앱 화면에서 검증하지 않았다.

Codex에 `ppomi` MCP를 등록했으며 실행 파일은 `/Applications/뽀미.app/Contents/MacOS/Ppomi`, 인자는 `["--mcp"]`다. Claude의 기존 영문 앱 이름 경로도 같은 최신 설치본 경로로 교체했고 다른 설정은 유지했다. 관리 앱의 기존 MCP 연결 재시작은 아직 실행하지 않았다. 별도로 최신 설치본과 직접 stdio 연결을 만들어 MCP 동작과 위의 Windows 조작 결과를 확인했으며, 이 확인을 Codex·Claude의 기존 연결까지 갱신된 것으로 간주하지 않는다. 개발 실행 파일도 갱신했으며 기존 외부 에이전트의 MCP 프로세스는 재연결해야 새 실행 파일을 사용한다.

## 다음 실기 확인

1. 현재 Windows 간편인증 창에서 통신사PASS가 선택된 상태다. 이번 당사자의 기본정보 프로필 등록 여부를 확인하고, 제공·등록되어 사용이 허용된 항목은 최신 입력칸을 검증해 자동 입력한다. 약관 확인과 동의·인증요청·휴대폰 PASS 인증은 당사자에게 넘긴다. 이전 공동인증서 파일 준비를 다시 요청하지 않으며, 사용자 완료 후 최신 화면으로 결과를 확인한다. 회원가입 경로를 다시 진행할 경우에는 최신 약관 화면의 필수·선택 항목을 읽고 당사자의 동의 단계로 넘긴다.
2. 일반 탐색과 제공·허용된 일반 폼 정보 입력을 계속한다. 자격 증명·본인 인증·새 동의 등 실제 사용자 단계가 나오면 필요한 행동과 완료 후 확인 기준을 보여 준다. 이 이후 화면과 입력의 실기 성공은 아직 확인하지 않았다.
3. 사용자가 인증 또는 필요한 접근 권한을 처리하면 최신 화면을 읽고 로그인 성공 여부를 확인한다. 초기화 실패가 계속되면 상태와 공식 안내를 근거로 다음 조치를 정한다.
4. 인증 후 대상 건축물·도면 구분·신청 또는 발급 경로를 확인한다. 결과 문서 또는 명시적인 발급 완료 상태가 있어야 취득 성공으로 기록한다.

이 기록 자체는 접근 권한 승인, 계정 생성 동의, 증빙 제출 승인, 설치·재설치 요청 또는 발급 성공 증거가 아니다.

## 후속 실기: 기본정보 자동입력 완료

최신 설치본에서 Keychain 프로필을 사용하는 `profile_fill`로 이름·생년월일·휴대폰을 입력하고, 화면과 MCP 응답을 확인했다. 통신사 선택도 유지됐다. 이름은 최초 입력 직후 OCR 검증이 실패했지만 포커스가 다른 칸으로 옮겨진 뒤 `already_filled: true`로 확인됐으며, 생년월일·휴대폰은 즉시 `verified: true`였다. 실제 값은 기록하지 않는다. 현재 대기 단계는 약관 확인·동의, 인증 요청과 휴대폰 PASS 인증이다. 로그인과 도면 수집은 아직 완료하지 않았다.
