# 뽀미(Ppomi) 디자인 작업 컨텍스트

## 앱이 무엇인가

2026-09-10 구현 기준. macOS 앱의 검은 작업대 창 하나가 선택한 제어창 뒤에 놓인다. 상단 기록은 요약을 기본으로 표시하고 필요할 때 전체 기록으로 펼친다. 하단은 왼쪽 대화(직접 구축한 뽀미 에이전트만), 오른쪽 제어 자리(iPhone 미러링·Android 미러·Parallels의 Windows 창)로 고정한다. 제어 자리 규칙은 Android 앱과 공통이다([UI 구조](../../docs/ui-structure.md)). 기록 펼침과 제어창 이동은 두 열의 역할을 바꾸지 않는다.

- 창: `Kiosk.swift`의 `MainPanel` 하나와 `Views/WorkbenchContent.swift`의 불투명 배경. 일반 창 레벨(`.normal`)에서 실제 대화창·제어창 뒤의 순서를 유지한다.
- 키오스크: 실제 외부 창의 자리를 제외한 영역을 `.screenSaver` 레벨 덮개로 가리고, 오른쪽 위 48pt X(또는 두 번째 Escape)로 나간다(`ImmersiveKiosk.swift`). 별도 Space·전역 제스처 차단·포커스 고정은 사용하지 않는다.
- 전환: 초록 버튼 또는 `⌃⌘F`. 아무 키나 누르면 나가기 X가 나타난다. 일반 창과 키오스크는 같은 기록·도구막대·승인 뷰를 주고받는다. Dock 아이콘으로 다시 열어도 기록 펼침 상태를 유지한다.
- 배치: `WorkbenchLayout`이 상단 기록과 하단 좌우 영역을 계산한다. 다시 배치·창 모드·디스플레이·기록 펼침·제어 대상 변경 같은 명시적 배치 요청에서 외부 창을 맞추고 실제 크기를 다시 측정한다. 일반 클릭·스크롤·타이머로 반복 축소하지 않는다. 사람이 제어창을 옮겨도 대화 열과 기록 영역은 고정된다.
- 기록: `RecordsPanelHost`가 요약과 전체 기록 화면을 유지하고, 전체 기록 보기의 `RecordsView` → `RecordsPageHost`가 타임라인 · 증빙·전표 · 절차 · 몸과 생활 페이지를 지연 생성해 캐시한다. 타임라인·증빙은 웹 뷰, 절차·몸과 생활은 네이티브 SwiftUI 뷰다. 요약으로 접거나 탭을 바꿔도 기존 페이지의 선택·스크롤·DOM을 유지한다.
- 상태·승인: `PhoneBand`를 대화 영역 하단에 고정한다. 기록과 대화 내용의 스크롤에 포함하지 않는다.
- 제어 크기: iPhone은 앱의 ‘보기 → 작게’ 메뉴를 한 번 요청한다. 2026-09-08 점검에서는 미연결 상태로 메뉴가 비활성화되어 실제 축소는 확인하지 못했다. Windows는 네이티브 창의 비율을 보존해 축소하며 PiP로 강제 전환하지 않는다. 메뉴 비활성 또는 앱의 최소 크기 제한은 실제 창 기준으로 처리한다.
- 배경·테두리: 배경은 검정. 폰 영역 테두리는 에이전트 작업 중 금색 2pt, 사람 차례 흰색 1pt, 대기 회색 1pt로 상태를 표시한다.
- 공통 CSS: `Web/theme.css`를 `Views/Web.swift`의 `Web.page()`가 각 웹 페이지에 주입한다.
- 사용자: 한국어 1인 개발자. 앱 문구는 한국어.

## 제약
- 작업대 배경은 검정이어야 한다(폰 베젤과 이어지는 배경). 금색은 에이전트 작업 상태를 표시하는 폰 영역 테두리에 사용한다.
- 다크가 기본(밤에 폰 옆에서 씀). 페이지 안에 밝은 종이 카드를 넣는 안도 후보로 검토 가능.
- 폰트: Inter는 로컬에 없을 수 있다 → -apple-system/Apple SD Gothic Neo 기본, 세리프는 Apple의 'New York'/Georgia 계열 가능. 외부 폰트 로드는 하지 않는다(오프라인).
- 기존 AppKit·SwiftUI·웹 뷰 구성 안에서 변경한다. 새 프레임워크·의존성은 추가하지 않는다. 뷰 소유·캐시·DOM 변경 원칙은 [UI 구조](../../docs/ui-structure.md)를 따른다.
