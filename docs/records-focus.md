# 기록 집중 모드

기록 헤더의 **기록에 집중**을 누르면 선택된 대화창과 제어창만 개별 최소화하고 기록 영역을 넓힌다. 하단에는 상태와 **작업으로 돌아가기**가 남는다. 돌아가기 또는 Esc로 같은 창을 복원하고 이전 기록 펼침 상태로 돌아간다. 페이지 객체, 선택된 전표와 3D 카메라 상태는 유지한다. y 좌표를 화면 밖으로 이동하거나 앱 전체를 숨기지 않는다.

창은 PID·WindowServer ID·AX 핸들로 검증하고 모든 대상의 최소화 가능 여부를 먼저 확인한다. 도중 실패하면 이미 접은 창을 복원한다. 창이 닫혔다면 새 창을 대신 만들지 않는다. 사용자가 직접 꺼내 이동한 창의 위치를 덮어쓰지 않는다. 일부 복원이 실패하면 오류를 표시하고 화면 제어 잠금을 유지한다.

집중 모드 동안 도킹·크기 맞춤·자동 재연결을 중단한다. 새 승인 요청, 화면 대상/대화 앱 변경 또는 디스플레이/Space 변경은 복원을 요청한다. 승인을 기다리거나 앱의 화면 작업이 진행 중일 때는 새 집중 모드를 시작하지 않는다.

## 화면 제어 경계

동일 원장 경로의 `.screen-control.lock`에 프로세스 간 `flock`을 사용한다. 새 버전 GUI의 집중 모드는 배타 잠금, MCP/음성의 화면 도구와 직접 수집은 호출 전체에 공유 잠금을 가진다. 집중 모드 중 차단된 MCP 호출은 예전 스크린샷도 반환하지 않는다. 원장 조회와 회계·공간 JSON 작업은 계속 가능하다. 커널 잠금이므로 프로세스 종료로 해제되며 지속되는 상태 플래그는 없다.

이 잠금은 이 버전의 뽀미 도구들에 적용된다. 이미 떠 있는 이전 버전 MCP는 클라이언트에서 다시 연결해야 한다. 다른 앱의 독립적인 CUA·브라우저 자동화를 중단하거나 재개하는 기능은 아니다.

검증: `RecordsFocusStateTests`, `RecordsWindowParkingTests`, `ScreenControlLeaseTests`와 화면 도구 잠금 통합 테스트 및 Workbench/Immersive 기하 테스트.

2026-09-08 통합 검증: 집중 테스트 84개 통과, 전체 Swift 테스트 402개 중 실패 0·조건부 실기/API 테스트 2개 생략. `/tmp/ppomi-focus-spatial-verification`의 실제 빌드 산출물을 사용했으며 stdio MCP 테스트도 같은 산출물을 실행한다.

설치 앱 GUI 검증: 21:06 설치본에서 선택된 Codex·Windows 창으로 집중/복원을 두 차례 확인했다. Esc와 하단 돌아가기 모두 동작했으며, 재집중 시 부동산 3D 탭과 가상 미리보기가 유지됐다. 실제 창에서 회전·확대·윤곽선·시점 초기화를 확인하고 집중을 해제했다. 공간 예시는 저장하지 않았다.
