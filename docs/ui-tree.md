# UI 트리 — 요구 조건 장부와 삭제 기록

머스크의 5단계를 작업대 트리에 돌린 기록이다. 순서는 (1) 요구 조건을 의심한다: 항목마다 요구한 사람의 이름이 붙어야 한다.
(2) 지운다: 지운 것의 10%를 되살리지 않았다면 덜 지운 것이다. (3) 그다음에야 단순화한다. (4) 주기를 줄인다. (5) 마지막에 자동화한다.
구조의 원본은 루트 `storybook/`(`cd storybook && npm run storybook`)의 **작업대**·**대화 셸** 스토리이고, 뼈대는 `agent/src/ui/`다.
Mac·Android는 이 구조를 따라 맞춘다(스토리북 먼저, 그다음 동일 적용).

## 1. 요구 조건 장부 (누가 · 무엇을)

| 요구 | 주인 | 판정 |
|---|---|---|
| 제어 대상 창이 앉는 빈 자리를 UI 안에 둔다 | 사용자 ("미러링 앱 공간을 비우는 UI") | 유지 |
| 큰 데이터 뷰가 필요하면 대상 창을 숨기고 기록을 넓게 본다 | 사용자 ("작업 타겟 윈도우를 숨기면 안되나") | 유지 = 기록 페이지 |
| 말은 최소, 색은 둘, 글꼴 하나, 다크, 큰 글자 | 사용자 | 유지 |
| Mac·Android 구조가 같다 | 사용자 | 유지 |
| 채팅과 음성 둘 다 | 사용자 | 유지 = 방식 탭 |
| 사람 차례(승인·질문)는 눈에 띄게, 코드 경계 안에서 | 사용자(결제 승인 규칙) | 유지 = 차례 띠 |
| 기록 요약 띠가 항상 위에 보인다 | 없음 (내가 "신뢰"를 이유로 넣음) | **삭제** |
| 기록 띠의 펼침(36%) | 없음 | **삭제** |
| 기록 띠의 양보(헤더 한 줄) | 없음 (내가 만든 충돌의 땜질) | **삭제** |
| 두 열 머리띠는 대칭 | 없음 (내 취향) | **삭제** (대화 열 머리띠) |
| 대화 열 아래 상태 푸터 | 없음 | **삭제** (셸 상태 줄이 이미 있음) |
| 제어 자리 "대기" 테두리 | 없음 | **삭제** (아무 일도 없을 때 표시할 것 없음) |
| 두 열 50/50 | 없음 | **삭제** → 제어 열 폭 = 대상 창 폭 |
| 셸 헤더(뽀미 + ⚙) | 없음 | **삭제** (제목 중복, 설정은 네이티브 설정으로) |
| 셸 안 서버 주소 폼 | 없음 | **삭제** → Mac 설정 창 · Android 설정 탭 |
| Android 기기 상태 aside + 허용 앱 목록 | 없음 | **삭제** → 미연결은 오류 띠 한 줄, 허용 앱은 대상 선택기 |
| 세션 안내문 | 없음 | **삭제** |
| 대화 열의 "저장한 내용"(기억) | 없음 | **삭제** |
| 기록 페이지의 기억 탭 | 없음 (row 위의 이동은 내 결정, 네이티브 기억 뷰 없음) | **삭제** |
| 제어 머리띠 새로고침 | 없음 (네이티브 미러링 앱이 스스로 재연결) | **삭제** |
| 제어 자리 "진행" accent 테두리 | 없음 (구멍에 폰 화면이 보이므로 진행은 이미 보임) | **삭제** → 상태 셋 |
| onSaved 콜백 · records.ts Memory 타입 | 없음 (기억 UI 삭제 뒤 남은 죽은 코드) | **삭제** |
| 셸 grid-area · --wait 토큰 · 셸 스토리의 workbench 스킨 | 없음 (지운 것의 잔해) | **삭제** |
| 음성은 대화 안의 통화(전화처럼 걸고·받고·끊기) | 사용자 ("페이스타임 하듯이 … 보이스톡 앱같은걸") | 유지 = 📞 버튼 · 통화 바 · 통화 카드 |
| 통화 중 주고받은 말이 로그에 말풍선으로 남음 | 사용자 (같은 요구) | 유지 = 통화 세션 전사(`callMessagesFromHistory`, 글 대화 투영은 그대로 음성 제외) |
| 사람 차례는 비서처럼: 먼저 톡, 답 없으면 재촉, 그래도 없고 급하면 전화 | 사용자 ("비서처럼, 먼저 톡에 용건을 넣은다음에 전화를 걸게 하자. … 답장이 없는데 급하게 결정해야 하는 경우에만 전화") | 유지 = 단계 셋. 0분 톡(`ppomiNotice` 말풍선 + 조용한 알림 "뽀미 · 용건") → 1분 재촉(알림 "아직 기다려요") → 3분 전화(`ppomiIncomingCall` + Mac 벨 / Android OS 통화). 벨은 45초면 부재중으로 끊고 톡은 남는다. 차례가 풀리면 모두 취소. Mac `Kiosk.askSub`, Android `VoiceSessionHost.turn`. 급한 정도(마감·되돌림 불가)로 단계를 당기는 건 요구 없음. 일일 결산 보고는 톡만, 전화 없음(정례 결산은 별도 성질) |
| 정례 결산(일일 보고) | 사용자 ("일일 결산 보고같은건 또 다른 성질") | 유지 = Mac 매일 21:00 `today_spending` 본문을 톡으로 한 장(`DailyReport`, `Kiosk.reportTimer`). 사람 차례가 아니므로 재촉·전화 없음. Android는 장부가 없어 해당 없음. 시각 설정은 요구 없음 |
| 걸려온 통화 받기 | 사용자 ("걸려온걸 받는 기능") | 유지 = 수신 띠. 트리거는 위 단계의 3분째(디버그는 즉시)가 `ppomiIncomingCall(용건)` 호출, 해결되면 `""`로 내림. 나중에 = `declineCall`(Android OS 벨도 끊김). 받기 = 통화가 열리고 뽀미가 용건을 한 문장으로 말한다. 승인·선택 자체는 네이티브 버튼(코드 경계)이고 통화는 설명만 한다. 앱이 꺼져 있을 때 걸려오기는 서버 측 에이전트가 생길 때(LiveKit/SIP 판단 보류) |
| 벨소리 + 시스템 알림 | 사용자 ("사운드가 안뜨니 오는지 모르겠네. 노티도 안뜨고") | 유지 = 페이지가 Web Audio로 울림(440·480Hz, 30초), Mac UNUserNotification. Android는 OS 전화(Telecom self-managed, `PpomiTelecom`)라 벨·진동·잠금 화면은 OS 몫 — 전체 화면 알림 권한(USE_FULL_SCREEN_INTENT)이 있어야 잠금 화면 위에 뜬다 |
| Android 전화 모드(카카오톡 보이스톡처럼) | 사용자 ("받았더니 잠금 그대로고 … 뺨 터치 보호 … 전화모드는?") | 유지 = `CallActivity` 하나: 잠금 화면 위에서 울림(거절·받기) → 받으면 잠금을 풀지 않고 그대로 통화 화면(연결 중 → 통화 중 m:ss · 스피커 · 대화 보기 · 끊기). 걸 때도 같은 화면. 귀에 대면 근접 센서로 화면 끔(수화기일 때만, 스피커·다른 화면에선 안 끔). 진행 중 알림을 누르면 이 화면으로 돌아온다 |
| 통화 중 승인은 말로도(구두 결재) | 사용자 ("승인도 그냥 전화 대답으로 하게 하던지 … 교본엔 어때") + 교본(구두 결재 = 복창 + 기록, 돈은 사후 서면) | 유지 = 뽀미가 금액·대상·수단을 복창하고 "승인이라고 말씀하시면 진행합니다"라고 청한다. 사람의 전사(`heard`)에 "승인"/"취소" 하나만 있으면 기기가 차례의 그 선택지를 누른다(`VoiceApproval`; 모델은 아무것도 승인하지 못한다). "네"만으로는 안 됨. 기록 = 전사 말풍선 + "말로 승인 · 용건" 말풍선. 잠긴 Android에선 무시(잠금 화면 결제 승인 금지) → "대화 보기"로 잠금 해제 |
| 통화 화면에 차례 띠 없음 | 규칙 (잠금 화면에서 결제 승인 금지) | 유지 = 잠긴 채로는 말로도 버튼으로도 안 된다. "대화 보기"가 잠금 해제를 요구한 뒤 대화(네이티브 버튼)를 연다 |
| 뽀미가 건 전화는 받자마자 뽀미가 먼저 말함 | 사용자 ("먼저 전화를 했으니 여보세요 하면 대답이 바로 있어야지") | 유지 = 받기 → 세션이 붙자마자 `response.create`(용건 한 문장, 용건 없으면 인사). 붙는 데 몇 초 걸리는 동안은 "연결 중" — 벨 울리는 동안 미리 붙이기는 요구 생기면 |
| 예약·판단으로 걸기(앱이 꺼져 있어도) | 사용자 (2026-09-10 논의) | 보류·설계만: 판단은 서버 규칙(납부일 전날·약 시간·승인 방치), LLM은 `schedule_call`로 예약만. 타이머 = Supabase pg_cron → Vercel 엔드포인트 → Android FCM; Mac은 상시 앱이라 표를 폴링해 스스로 울림(APNs는 서명 상태로 불가). iPhone 해당 없음 |
| 로그 = 현재 세션 | 규칙 (종료 시 대화 삭제) | 통화 카드·전사는 다음 글 대화가 시작될 때 함께 사라진다. 한 로그에 여러 토막을 남기려면 고정 사본이 필요 — 요구 없음 |
| 끝 카드의 길이·요약 | 없음 (요약 생산자 없음, 1분 미만은 거짓) | **삭제** |
| 카드·수신 띠의 장식 📞 | 없음 (입력창 📞만 주인 있음) | **삭제** |
| 음소거 코드 · 수신 출력 잔재 · 음성 입력 워크릿 · 애니메이션 | 없음 (지운 UI의 잔해) | **삭제** |
| 상태 띠의 × (미설정·미연결) | 없음 (초점 복귀 때 이미 재확인) | **삭제** |
| 방식 탭(채팅|음성) | 없음 (통화 모델이 대체) | **삭제** |
| orb · 음성 무대 · 음성 바 · "음성 시작" | 없음 (통화 바 한 줄 + 끊기가 대체) | **삭제** |
| 첫 화면 힌트 + 제안 하나 | 사용자(어르신) | 유지 |
| 닫힌 폴드·작은 Mac 창에서는 제어 열이 레일 한 줄로 접히고, 펼친 폴드·큰 창에서는 왼쪽이 닫힌 화면 그대로 + 오른쪽 제어 열 | 사용자 ("통일성", 2026-09-10) | 유지 = 크기 클래스 둘(840px 컨테이너 쿼리), 차례 띠는 접히지 않음 |
| 도구 카드(로그 안, 시간순) | 사용자(무슨 일이 있었는지) | 유지, 접힘(실패는 펼침) |
| 대화 열의 상태 한 단어(role=status) | 없음 (채팅은 스트리밍 '…'·도구 요약·질문 카드에 이미 보임) | **삭제** → "설정에서 서버 주소"만 오류 띠로. 음성 무대는 한 단어를 둔다(아래 되살린 것) |
| 대화 열 머리 종료 버튼 | 없음 (네이티브가 패널 닫힘 때 ppomiVoiceStop을 부름) | **삭제** (사람이 세울 수단이 필요하면 사용자 주인으로 되살림 — 10% 후보) |
| tokens.css .num 규칙 | 없음 (agent/src에 쓰는 곳 없음, 페이지 스킨 theme.css가 자체 정의) | **삭제** |
| /v1/memories/delete 서버 경로 + Mac·Android 허용 경로 | 없음 (기억 탭 삭제 뒤 클라이언트 없음) | **삭제** — 스트림 밖(agent/server, AgentNative.swift, VoiceBridgePolicy.java), 해당 담당 |
| Shell `voice` prop → `.voice-mode` 클래스 | 없음 (어디에도 선택자 없음, 예전 음성 레이아웃의 잔해) | **삭제** |
| `ConversationTop` 감싸개 + `.conversation-top` | 없음 (종료 버튼 삭제 뒤 자식 하나짜리 flex) | **삭제** → 방식 탭을 `top`에 직접, `.mode-tabs { align-self: flex-start }` |
| 첫 화면 제목 h1 "무엇을 할까요?" | 없음 (35행은 힌트 + 제안 하나만 이름함, 힌트와 목적 중복) | **삭제** |
| 음성 음소거 / 마이크 켜기 버튼 + `muted` 상태 | 없음 (16행은 음성 방식 자체지 음소거가 아님) | **삭제** — `VoiceController.mute()`는 voice.ts(스트림 밖, voice.test.ts가 덮음)에 남아 그 담당의 죽은 코드 |

되살린 것(10% 규칙):
- **정지** — 주인: 사용자(결제 승인 규칙 · 코드 경계, 17행). 종료 버튼 삭제 뒤 폰을 누르는 뽀미를 사람이 세울 길이 없었다(방식 탭은 진행 중 잠김, 보내기는 대기 중 잠김, ppomiVoiceStop은 패널 닫힘뿐). 새 요소 없음: 채팅은 대기 중 보내기 버튼이 정지로 바뀌고, 음성은 진행 중 음성 바에 정지 하나. 둘 다 stopCurrent.
- **음성 무대의 한 단어** — 주인: 사용자(말은 최소·큰 글자·어르신, 14·35행) + 접근성 기본. 연결 중 / 듣는 중 / 말하는 중 / 진행 중. orb의 유일한 신호는 숨쉬기 속도인데 reduced-motion이 그걸 끄고, role=status에 읽을 글자가 없었다. `.voice-stage` 안 `<p>` 하나. 채팅은 그대로 없음.
- 후보: "연결 끊김" 한 줄 — 제어 자리 안에만 둔다.

## 2. 삭제 뒤의 트리

```
작업대                              div.workbench
├─ 작업 공간                         div.workspace   열: 대화 = 남는 폭 · 제어 = 대상 창 폭
│  ├─ 대화     section.conversation  Shell: 수신 띠(걸려올 때만) · 도구 요약 · 로그(힌트+제안 | 말풍선 | 통화 카드 | 질문 카드) · 입력(📞 · 보내기|정지) 또는 통화 바(한 마디 · 끊기)
│  └─ 제어     section.control       머리띠(대상 ▾ · 기록) + 자리
│     └─ 자리  div.control-slot      차례 = 잉크 테두리 · 그 외 테두리 없음. 비어 있으면 한 줄(대상 이름 / 연결 끊김 / 뽀미 진행 중)
└─ 차례 띠     footer.turn           사람 차례일 때만: 질문 한 줄 + 버튼. 제어 열 아래

기록 페이지                          작업 공간을 통째로 대체. 머리띠(대화로 돌아가기) + 탭: 타임라인 · 증빙 · 분개 · 절차 · 건강 · 3D
```

상태는 셋: 대화(자리 비어 있음, 진행 중이면 한 줄) · 차례 · 기록. 크기 클래스는 둘: compact(< 840px: 제어 열 → 대화 위 레일 한 줄, 구멍 없음) · expanded(≥ 840px: 위 트리 그대로). 스토리는 셋 × 둘. 대화 셸은 처음 · 대화 중 · 통화 중 · 걸려옴 · 통화 끝 · 오류 · 미설정 · Android 미연결.

## 3. 단순화 (삭제 뒤에만)

- 간격 값 하나(.75rem). 고정 높이 없음. 차례 띠는 있을 때만 높이를 가진다.
- 제어 열 폭 = 대상 창 폭 + 간격 2. 대상이 없으면 최소 폭(iPhone 폭).
- 사람 차례 신호는 띠(질문 + 버튼)가 주고 테두리는 보조다.

## 4. 주기 · 자동화

- 주기: 구조 변경은 스토리북 스토리 셋을 고치는 일이다. 툴바로 테마·글자 크기를 같은 조건에서 본다.
- 자동화: 색은 `agent/scripts/generate-theme.mjs`가 세 플랫폼으로 생성. 레이아웃 값(간격·최소 제어 폭)도 같은 방식으로 생성할 후보.

## 5. 주입 계약

- 서브트리: `ReactNode` prop. 뼈대는 위치만 정한다.
- 스타일: 컴포넌트는 클래스 이름만 낸다. 색·크기는 `tokens.css`, 모양은 `style.css`/`workbench.css`.
- 상태: `main.tsx`만 브리지를 안다. 뼈대에는 값과 `onX`만 들어간다.
- 네이티브: Mac `WorkbenchLayout`·Android `rememberControlSlot`이 같은 트리를 pt/dp로 만든다.
