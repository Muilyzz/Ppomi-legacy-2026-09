# 사업자 공동인증서: 발급 준비부터 원래 업무 복귀까지

이 절차는 발급기관을 미리 정하지 않는다. 이번 당사자의 기존 사업자 인터넷뱅킹과 인증서·진행 중 신청을 먼저 확인한다. 이미 세션에서 정한 내용을 다시 묻지 않고 준비 가능한 탐색과 폼 확인을 계속한다. 사용자는 실제 비밀 입력·본인 확인·기존 승인 범위 밖의 동의·권한·결제가 필요한 순간에만 개입한다. 개인·가족·다른 사업자의 계정과 인증서를 현재 사업자의 것으로 가정하지 않는다.

## 시작: 현재 상태와 발급 경로

1. 원래 업무, 신청 권한, 기존 인증서 유무와 현재 발급 진행 상태를 세션·공식 화면으로 확인한다. 세움터 사업자 가입을 위한 경우 개인 인증서가 아닌 해당 사업자의 공동인증서가 필요한 흐름인지 현재 사업자인증 화면에서 확인한다.
2. 사용 중인 **사업자 인터넷뱅킹**의 은행이 이미 알려져 있으면 그 은행의 공식 기업 인증센터를 먼저 확인한다. 개인 계좌나 개인 인터넷뱅킹 보유만으로 사업자 발급 자격을 추정하지 않는다. 은행 정보가 없으면 은행명 또는 사업자 인터넷뱅킹 미이용 여부만 확인한다. 비밀번호·계좌번호·OTP를 채팅으로 요구하지 않는다.
3. 기존 인증서가 있으면 공식 관리 화면에서 현재 기기의 저장소·용도·유효 상태를 확인한다. 인증서가 한 저장소에서 안 보인다는 이유로 없는 것으로 단정하거나 새로 결제하지 않는다. 발급기관·당사자가 확인한 가져오기나 복사 경로를 준비할 수 있지만 인증서 파일·개인키·암호를 에이전트에게 전달하게 하지 않는다.
4. 진행 중인 신청이 있으면 현재 신청의 **이어가기**를 찾는다. 새 발급, 갱신, 재발급, 다른 기기로 복사하기는 서로 다른 작업이다. 새 발급 요청만으로 기존 인증서를 삭제·폐기·재발급하지 않는다. 기존 인증서에 미치는 영향이 불명확하면 그 안내를 먼저 확인한다.
5. 사용할 은행 경로가 없으면 발급기관별 신청 자격·서류·기간·비용을 비교하고 사용자가 선택한 경로를 준비한다. 이 패키지의 `launch.search`는 [한국정보인증의 개인사업자 비대면 안내](https://www.signgate.com/entprsUntact/entprsOgcrAply/main.sg)다. 안내 주소가 등록되어 있다는 이유로 이 업체나 유료 상품을 자동 선택하지 않는다.

### KB 경로: 기존 공동인증서 재사용 우선

- 선택된 은행이 KB이면 [KB 기업 인증센터](https://obranch.kbstar.com/quics?page=C100996)의 현재 공동인증서 메뉴를 확인한다. 무료로 안내되는 **KB국민인증서(기업)**를 공동인증서와 혼동하지 않는다. 특정 사용자의 은행·인증서 보유·저장 위치는 공개 패키지의 기본값으로 기록하지 않는다.
- 기존 공동인증서가 있으면 용도·유효 상태·실제 저장 위치부터 확인한다. [KB 인증서 관리](https://obank.kbstar.com/quics?page=C101062)의 보기·검증, PC↔USB 복사·가져오기 또는 [스마트폰 인증서 복사](https://obank.kbstar.com/quics?page=C101065)를 원래 저장 매체에 맞게 준비한다. 인증서 파일·개인키·암호는 에이전트에게 보내지 않는다.
- [KB 재발급 FAQ](https://obank.kbstar.com/quics?articleId=928&bbsMode=view&boardId=690&page=C019799)는 재발급 시 다른 PC에 있던 기존 인증서도 자동 폐기된다고 안내한다. 다른 기기에서 쓰려는 목적이면 복사를 먼저 검토하며, 재발급 화면이 있다는 이유로 진행하지 않는다. 재발급이 실제 필요한 경우 기존 사용처에 미치는 효과와 당사자 의사를 먼저 확인한다.
- [KB 프로그램 안내](https://obank.kbstar.com/quics?page=C034282)의 HTML5 G4 브라우저 저장은 KB에서만 사용할 수 있다고 명시되어 있다. 그 저장 성공을 세움터용 인증서 준비 완료로 보지 않는다. 선택한 복사 방식으로 인증서가 **Parallels Windows에서 실제 접근 가능한 저장 매체**에 도착했는지 확인하고, 세움터의 인식·인증은 별도로 검증한다. KB 프로그램의 ARM·Parallels 호환은 아직 실기로 검증하지 않았다.

### KB 발급·재발급 선택이 이미 확정된 경우

1. KB 경로와 발급·재발급 선택을 현재 세션에서 이어받는다. 기존 인증서 폐기 영향까지 설명되고 재발급이 명시적으로 허용되었다면 같은 허가를 다시 묻거나 기존 인증서 복사 비교로 되돌리지 않는다. 승인이 달라진 새 효과·비용·권한만 실제 화면에서 구분한다.
2. 기존 Parallels Windows에서 [KB 기업 인증센터](https://obranch.kbstar.com/quics?page=C100996)를 열어 현재 [사업자 공동인증서 발급·재발급](https://obank.kbstar.com/quics?page=C019623) 경로를 확인한다. 화면의 인증서 종류·단계·필수 입력을 읽고 허용된 일반 정보를 준비한다. 현재 표시되지 않은 은행 필드나 버튼을 추측하지 않는다.
3. 이미 허용된 준비와 동의는 이어가고, 은행 비밀번호·본인 인증·OTP·새 인증서 비밀번호는 실제 입력 화면을 준비한 다음 당사자에게 넘긴다. 수수료가 있으면 선택 상품·최종 금액을 확인하고 기존 결제 승인 경계를 따른다.
4. 발급 화면에서 현재 지원 저장 매체를 확인한다. USB가 연결되어 있고 직접 저장이 실제로 지원되면 선택한 USB에 저장을 준비할 수 있다. USB가 없으면 지원되는 Windows PC 저장소에 발급한 뒤 아래 USB 복사 절차를 나중에 이어간다. USB 부재를 이유로 발급 준비 전체를 사용자에게 넘기지 않는다.
5. 공식 완료 안내와 원본 저장소의 새 인증서를 확인한다. 주체·용도·유효기간을 필요한 범위에서 확인하되 원문을 공개 기록에 남기지 않는다. 인증서 발급·세움터 인증·USB 복사 완료는 각각 따로 검증한다.

### KB ID를 모르는 경우: 실제 조회 폼 준비

1. 발급 1단계의 `ID를 모르시는 경우`를 열고 현재 ID 조회 팝업을 읽는다. 기존 세션에서 개인사업자·법인사업자가 확인됐으면 다시 묻지 않고 해당 유형을 선택한다. 개인사업자는 고객명·생년월일·출금계좌번호·계좌 비밀번호를 요구하는 화면을 확인했다. 법인에 같은 항목을 적용하지 않는다.
2. `profile_status`로 이번 당사자의 생년월일과 `bank_profiles`의 KB 고객명·출금계좌번호 등록 여부를 확인한다. 통장 고객명은 기존 이름·상호를 임의 조합하지 않는다. 뽀미 Mac 채팅에서는 `request_bank_profile`의 전용 카드로 미등록 고객명·계좌번호만 받는다. 이 카드가 없는 호스트에서는 뽀미 설정의 자동입력 기본정보에서 직접 등록할 수 있도록 준비한다. 계좌 원문을 일반 질문·도구 인자·플레이북으로 수집하지 않는다.
3. 확인된 개인사업자 ID 조회 팝업에서 `profile_fill(form: kb_id_lookup, bank_id: kb)`로 `bank_customer_name`, `birth_date`, `bank_account_number`를 한 항목씩 입력한다. 좌표는 현재 빈 폼에서 확인하고 각 호출이 로컬에서 주소·양식·포커스를 재검증하도록 한다. 생년월일은 저장된 날짜를 YYMMDD로 변환한다. 비공개 입력 후 일반 화면 캡처로 원문을 기록하지 않는다.
4. 전용 도구가 거절하거나 반영 여부가 불확실하면 원인을 확인하고 입력을 반복하지 않는다. 계좌 비밀번호·OTP·전체 주민번호를 저장하거나 채팅으로 요청하지 않는다. 실제 공식 입력 화면에서 필요한 비밀번호 인증만 당사자에게 넘긴다. ID 조회 결과와 발급 본인확인 결과는 따로 확인한다.
5. 계좌 확인에 필요한 iPhone이 없거나 사용자가 잠시 자리를 비웠으면 해당 단계를 보류하고 다른 준비를 진행한다. 미러링 연결·잠금·같은 미완료 요청을 반복하지 않는다. 복귀 후 현재 은행 세션과 새 화면을 확인해 계좌 확인 단계부터 재개한다.

## 인증서 종류·용도·비용 확인

- **공동인증서와 금융인증서는 별도 방식**이다. 사이트의 공동인증 버튼을 금융인증서 발급으로 대체하지 않는다. 은행 인증센터에서 현재 선택하는 메뉴·인증서 종류를 읽는다.
- 은행용 사업자 공동인증서와 사업자 범용 공동인증서는 용도와 비용이 다를 수 있다. [KB국민은행 기업 인증서 안내](https://obranch.kbstar.com/quics?page=C019646), [IBK기업은행 기업 인증서 안내](https://kiup.ibk.co.kr/IBK/uib/ecb/tutorial/html/info.html)처럼 **선택한 은행의 공식 안내**에서 실제 조건을 확인한다. 은행 안내의 전자민원 지원 문구만으로 세움터의 해당 사업자인증에 사용할 수 있다고 단정하지 않는다.
- 2026-09-09 조사에서 IBK의 사업자 은행·보험·신용카드용 연간 수수료는 부가세 포함 4,400원으로 안내되었다. 그러나 **세움터 사업자인증의 허용 인증서 정책 OID는 아직 확인하지 않았다.** 이 가격의 상품이 세움터에 호환된다고 약속하지 않는다. 범용 상품도 실제 세움터 인증 결과를 확인하기 전에는 성공으로 기록하지 않는다.
- 한국정보인증 비대면 사업자 범용 1년 안내는 100,000원에 부가세가 별도여서 합계는 110,000원이다. 이는 공개 안내의 당시 금액이며 결제 승인이나 기본 선택이 아니다. 기간·상품·최종 청구액은 현재 화면에서 다시 확인한다. 필요 용도와 호환 근거가 없는 상태에서 범용 상품을 자동 선택·결제하지 않는다.
- **전자세금계산서 전용 인증서는 이번 세움터 가입을 위한 신규 발급 후보에서 제외한다.** 전용 상품의 목적과 세움터 사업자인증을 혼동하지 않기 위한 선택 기준이며, 모든 시스템에서 기술적으로 거절된다는 뜻은 아니다.
- 선택한 상품의 용도·세움터 호환 근거가 여전히 부족하면 `호환 미확인` 상태를 유지한다. 상품 선택이나 결제로 불확실성을 감추지 않고 발급기관·세움터 공식 안내에서 필요한 확인을 준비한다.

## Parallels Windows에서 준비

1. 이 작업은 사용자가 지정한 기존 Parallels Windows를 이어 쓴다. `windows_screen`으로 VM과 현재 브라우저·팝업을 확인하고, 대기 상태면 실제 Parallels 재개 화면을 준비한다. 창 모드·입력 포커스·화면 갱신 여부를 구분한다. 화면을 읽을 수 있다는 사실만으로 입력이나 사이트 인증이 정상이라고 보지 않는다.
2. 선택된 공식 발급기관·은행 주소는 `windows_open(target: 현재 확인한 공식 URL)`로 연다. 이 패키지의 웹 `launch.target`은 공통 스키마의 `browser`이며 `browser_open`은 Mac Chrome을 여는 도구다. 이미 지정된 Windows 작업을 그 기본 실행 동작 때문에 Mac으로 옮기지 않는다. 은행을 선택했는데 `windows_open(app: joint-certificate)`로 한국정보인증 안내를 대신 열지 않는다.
3. 실제 연결된 브라우저 DOM 도구가 있으면 현재 역할·라벨·상태를 우선 사용한다. **현재 Parallels 게스트 브라우저에는 연결된 DOM 브리지가 없다.** Mac Chrome DOM을 Windows Edge 화면의 증거로 쓰지 않는다. 현 환경에서는 `windows_screen`의 최신 화면·OCR와 `windows_click`·`windows_key` 등 현재 도구로 이어가며, DOM 검증을 했다고 기록하지 않는다.
4. 클릭·키 전송의 성공 응답만으로 화면 전환을 확정하지 않는다. 현재 입력 포커스와 새 팝업·오류를 읽고, 같은 신청·결제·인증 요청을 무작정 반복하지 않는다. 보호 도구가 거부하면 원인과 화면을 확인하며 다른 도구·좌표·키로 같은 보호 동작을 우회하지 않는다.
5. 공식 보안 프로그램의 현재 안내와 필요한 설치 상태를 확인한다. 이번 발급 요청과 기존 승인에 포함되는 공식 다운로드·설치·기본 연동 설정 및 일반 확인 버튼은 이어서 처리한다. 새 설치창이나 권한 화면이라는 이유만으로 같은 허가를 다시 묻지 않는다. 실제 OS 관리자 암호·본인 인증 또는 기존 범위를 벗어난 민감 접근 권한이 필요한 지점에서만 화면과 필요한 행동을 준비해 당사자에게 넘긴다. 설치 완료는 인증 성공과 구분한다.
6. KB 설치 프로그램이 종료됐는데도 설치 안내가 반복되면 같은 설치를 재실행하기 전에 현재 은행 도메인의 브라우저 사이트 권한을 확인한다. 이번 Windows Edge 실기에서는 `obank.kbstar.com`의 `디바이스의 앱`이 자동 차단되어 있었다. 허용된 인증 프로그램 연동 범위에서 해당 사이트 설정을 변경하고 새로고침한 뒤 설치 안내가 사라지는 것을 확인했다. 이를 다른 사이트의 권한이나 전역 보안 설정 변경으로 확대하지 않는다. 설치 안내가 사라져도 실제 인증·발급 성공은 다음 단계에서 별도로 확인한다.

## 기관별 신청 요건

선택한 기관의 최신 요건을 읽는다. 아래 한국정보인증의 제한을 모든 발급기관의 공통 제한으로 확대하지 않는다.

- **한국정보인증 비대면 경로**는 대표자가 한 명인 개인사업자가 대표자 본인으로 신청하는 경우를 대상으로 한다. 법인·공동대표·대리인은 이 경로의 자격을 충족한다고 선택하지 않는다. 대상이 다르면 기존 은행이나 해당 기관의 다른 공식 경로를 준비한다.
- 한국정보인증 안내에는 대표자 소유 휴대폰과 계좌, 신분증을 이용한 본인 확인 및 사업자등록증명원이 요구된다. 사업자등록증과 사업자등록증명원을 같은 서류로 처리하지 않는다.
- 한국정보인증 제출용 사업자등록증명원은 신청일을 포함해 7일 이내 발급분을 요구한다. 정부24 **앱**에서 마련한 전자문서지갑으로 제출하며 제출처는 한국정보인증이다. 해당 안내는 주민등록번호 전체가 표시된 증명서를 요구한다. 발급일·제출처·표시 범위를 현재 공식 화면에서 확인한 뒤 당사자가 민감 서류의 발급과 제출을 직접 처리한다. 신분증이나 주민등록번호 전체를 대화·플레이북·공개 파일에 받지 않는다.
- 다른 경로가 필요하면 [한국전자인증 비대면 안내](https://www.crosscert.com/landing_page_glca/index.jsp) 등도 비교할 수 있다. 조사 당시 이 안내는 1인 대표 개인사업자와 법인 대표자 본인의 신청을 안내했으며, 신분증·셀피 및 최근 증명서와 법인 추가 서류가 포함되었다. 외국인은 제외되며 등기부등본이 없는 비영리·공공기관 법인 등은 제한될 수 있다. 사업자용과 개인용을 묶은 상품을 자동 선택하지 않는다. 그 기관의 현재 자격·서류·심사 시간을 별도로 확인하고 한국정보인증의 자격이나 승인 상태를 그대로 이식하지 않는다.

## 신청·인증·결제·서류 제출

1. 현재 신청 화면에서 필수·선택 항목, 약관, 실제 단계 순서를 읽는다. 한국정보인증 안내에서 신청정보 다음에 휴대폰·계좌·신분증 확인, 결제, 서류 제출·확인, 발급 순서가 표시되지만 다른 기관에 같은 순서를 강제하지 않는다. 단계 안내는 각 단계의 실기 성공을 뜻하지 않는다.
2. 이미 제공되었고 해당 기관 사용이 허용된 일반 신청 정보는 현재 폼에 준비한다. 필요한 정보가 없을 때만 질문한다. **`profile_fill(form: eais_business)`와 `eais_pass`는 세움터 전용**이다. KB 개인사업자 ID 조회에는 위 전용 `kb_id_lookup`만 사용하며 다른 은행·발급기관·정부24 양식에 확대하지 않는다. 전용 도구가 거부한 개인정보를 일반 입력 도구로 옮겨 재시도하지 않는다.
3. 동의가 표시되면 현재 내용·필수 여부·효과와 기존 승인 범위를 확인한다. 같은 요청에 포함된 필수 동의는 재질문 없이 처리하고, 기존 범위를 벗어나는 동의만 내용이 보이는 실제 화면에서 필요한 승인을 요청한다. 선택 개인정보·마케팅을 전체 동의로 묶지 않는다.
4. 휴대폰 본인 확인, 계좌 확인, 신분증 촬영·셀피, OTP·보안매체 입력은 공식 화면을 열어 놓은 다음 당사자에게 넘긴다. 계좌점유 확인을 임의 송금으로 대신하지 않는다. `현재 화면 → 필요한 한 가지 행동 → 완료 뒤 확인할 상태`로 안내하고 일반 절차 전체를 사용자에게 떠넘기지 않는다.
5. 비용이 실제로 발생하는 시점에는 선택한 인증서·기간·부가세 포함 금액·결제수단을 보여 준다. Windows 자동 결제는 기존 `confirm_payment`의 승인 1회·결제 클릭 1회 경계를 따른다. 결제 인증은 당사자가 처리하며, 이 플레이북 자체는 승인 증표가 아니다. 결제 결과가 모호하면 접수 상태를 먼저 확인하고 다시 결제하지 않는다.
6. 민감 증명서 제출에는 실제 공식 제출처와 요구 범위를 준비한다. 당사자가 공식 앱·웹에서 처리하도록 하고 민감 문서 화면을 지속 캡처하거나 원문을 기록하지 않는다. 완료 알림 뒤 민감값이 없는 상태 화면에서 접수·검토 결과를 확인한다. 문서를 전송했다는 사실과 발급 심사 통과를 구분한다.

## 이어가기·발급 완료·세움터 복귀

1. 중단 후에는 홈의 현재 `신청이어가기` 같은 공식 진입점에서 **기존 신청 상태**를 확인한다. 오래된 인증 URL·세션 토큰·과거 좌표를 저장해 재사용하지 않는다. 사용자 완료 알림만으로 심사나 발급 성공을 추정하지 않는다.
2. 신청 접수, 결제 완료, 서류 제출, 심사 중, 발급 가능, 발급 완료를 구분한다. 심사 대기는 즉시 실패가 아니다. 발급기관이 새 인증·동의를 요구하면 실제 달라진 단계만 준비한다.
3. 발급 가능한 화면에서 현재 지원 저장 매체를 확인하고 당사자가 선택한 Windows 저장소를 준비한다. 새 인증서 비밀번호 설정·전자서명은 그 실제 화면에서 당사자가 직접 수행한다. 암호·개인키·발급 비밀·인증서 원문을 에이전트에 보내 달라고 하지 않는다.
4. 공식 발급 완료 안내와 선택한 저장소에서의 인증서 표시를 확인한다. 당사자 일치·유효기간·용도는 필요한 범위에서 확인하되 인증서 주체 정보·일련번호·비밀을 공개 기록에 복사하지 않는다. 결제만 끝난 상태나 저장 버튼 클릭을 발급 완료로 기록하지 않는다.
5. 원래 업무가 세움터 사업자 가입이면 `eais` 플레이북으로 돌아가 현재 가입 유형·단계·세션을 새로 확인한다. 만료된 사업자인증 창은 재사용하지 않는다. 기존 승인 범위의 일반 준비와 필요한 전용 사업자 정보 입력을 이어가고 인증서 선택·암호 입력 화면을 준비한다. 실제 인증서 암호와 본인 승인은 당사자가 처리한다.
6. **인증서 발급 성공, 세움터 인증서 인식, 사업자인증 통과, 회원가입 완료는 각각 별도 결과**다. 인증서가 목록에 표시되어도 세움터가 허용하는 정책·용도인지 또는 사업자 인증에 성공했는지는 다음 공식 응답으로 확인한다.

## USB 연결 뒤 새 인증서 복사·검증

1. USB가 연결되면 기존 Parallels의 장치 연결 화면과 Windows에서 실제 마운트된 매체를 확인한다. [Parallels 외부 장치 연결 안내](https://docs.parallels.com/landing/pdfm-ug/parallels-desktop-for-mac-26-users-guide/use-windows-on-your-mac/connecting-external-devices)를 참고해 현재 표시된 `Devices → USB` 계열 메뉴나 연결 팝업에서 해당 Windows VM을 선택한다. 메뉴 이름·버전은 현재 화면을 다시 읽는다. Mac의 공유 볼륨·네트워크 드라이브와 USB 직접 연결을 구분하며, Mac에 꽂혔다는 사실만으로 Windows 연결을 확정하지 않는다. 장치가 없으면 PC 원본을 유지한 상태에서 `USB 연결 후 복사 재개`로 남긴다. 포맷·삭제로 장치를 준비하지 않는다.
2. [KB 공식 USB 인증서 복사](https://obank.kbstar.com/quics?page=C101172) 또는 [인증서 관리](https://obank.kbstar.com/quics?page=C101062)의 복사 기능을 열고 원본 저장소에서 **새로 발급한 인증서**의 주체·용도·유효기간을 확인한다. 공식 안내의 원본 선택·USB 연결·복사·저장 위치·암호·완료 순서를 현재 화면에 맞춰 이어간다. 이미 발급 화면에서 USB에 직접 저장했다면 다시 복사하기 전에 USB 쪽 목록 확인부터 진행한다.
3. 현재 확인한 USB를 대상 저장소로 선택하고 기존 인증서와의 충돌 여부를 읽는다. 포맷·삭제·덮어쓰기 요청을 자동 처리하지 않는다. 다른 매체를 임의로 선택하지 않고 충돌이 있는 현재 화면에서 필요한 결정만 확인한다.
4. 암호가 필요한 실제 복사 화면을 준비한 뒤 당사자가 직접 입력하도록 한다. 나머지는 은행 UI의 정상 복사 절차로 이어간다. 개인키·PFX/P12·인증서 파일·암호를 에이전트, 채팅, 공개 산출물로 복사해 중계하지 않는다.
5. 성공 안내 뒤 **USB를 선택한 인증서 목록·보기 화면**에서 해당 새 인증서를 다시 확인한다. 원본 PC 목록에만 나타나거나 복사 버튼을 눌렀다는 사실은 USB 복사 성공이 아니다. USB에서 주체·용도·유효기간을 확인한 범위와 아직 확인하지 못한 업무 인증 결과를 구분한다.
6. USB 복사 검증과 실제 전달은 별개다. USB를 누구에게 언제 전달할지는 사용자가 담당하며, 실제 대행 관계·수령인·연락처를 공개 플레이북에 기록하지 않는다. 전달했다고 추정하거나 자동으로 외부에 인증서를 보내지 않는다.
