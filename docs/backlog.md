# AssetManager · 2026-09-03 기획·검증 기록

> 당시 기획과 검증 결과를 보존한 문서이며 현재 구현 지침이나 작업 목록이 아니다. 아래의 Swift 단독·CloudKit·서버 없음·웹뷰 제거·도넛·검은 띠 네 장·두 번 누르기 종료는 과거 계획 또는 구현 설명이다. 현재 구조는 [README](../README.md)와 각 기능의 코드·테스트를 확인한다.

한 파일에 전부 둡니다. 완료는 검증된 것만, 미구현은 아이디어 단계까지 포함. 우선순위 ★는 "다음에 손댈 것".

## 1. 완료 (동작 확인됨)

### 수집 (Python am.py + phone.swift)
- KB국민ONE통장 거래내역조회 파서, 앱별 `tx/txpage/home/scroll_y` 설정, KB 웹뷰 스크롤(y=0.7), `TX_DAYS` 소급, 페이지 상한 120.
- 원본 보존: 스크린샷마다 OCR `.jsonl` 영구 보관(PNG는 7일).
- 미러링 상태를 접근성 트리로 읽음(`phone state`), 이벤트 감시(`phone watch`), `axdump`.
- 기준 좌표 하나: `phone place center`(`homePoint`), am.py는 `MIRROR_AT`(기본 center).
- 키오스크 `phone kiosk`: 검은 띠 4장, 창 고정, 2px 테두리, 두 번 누르기 종료, 왼쪽 띠 WKWebView(timeline.html).
- 테스트 `test_am.py` 통과(KB 샘플 포함, 날짜 고정).

### 보고서 (report.py, HTML 4장 + 타임라인)
- 1 증빙·전표: OCR 글자를 좌표 그대로, 색·크기는 원본 픽셀에서, 우측 정렬 고정, 호버 = 블링크 비교기, 이상만 상자, 잔액 사슬 검산.
- 2 분개장: 양끝 계정만 저장, 유형은 읽을 때 렌즈로(`classify`).
- 3 대차대조표: 월초·월말, 측정/이월/미측정 배지.
- 4 실체: React Flow 캔버스, 캡처에서 오려낸 앱 아이콘, 경계 사각형, 렌즈 버튼.
- timeline.html: 순자산 계단선, 하루 클릭, 기간 칩, 관측 vs 설명 vs 미관측 막대. 같은 분 정렬(`chain_order`) 수정.

## 2. 결정 (바꾸려면 다시 논의)
- 이체 자동화는 하지 않는다. 준비까지만, 승인은 사람이 기기에서. 한도는 은행에서.
- 주 경로는 앱 화면 미러링 하나. 문자·엑셀·API는 덤.
- 스택은 Swift 하나. 규칙·뷰·보고서(=뷰의 PDF)까지. Python은 파서 이식 뒤 퇴장. 웹뷰는 끝에 0.
- 서버 없음. CloudKit 개인 DB(동기화·백업) + 공유 DB(가족, 마디 단위 공유, 소유자가 내줌).
- 기기 역할: 맥 = 몸통(수집·키오스크·개발자 작업대·음성), 아이패드 = 상담(개인·가족), 아이폰 = 열쇠·주머니.
- 일일 결산: 밤에 폰이 잠겨 맥 옆에 있을 때 한 번. 빠진 날은 다음 마감이 덮음.
- 경계는 렌즈: 분류는 읽을 때, 저장은 양끝만. 계좌/폴더/실체 세 낱말.
- 부모님: 폴더블은 메신저, 금융은 전용 아이폰(전 은행), 비상용 KB는 안드로이드에 은행 한도로.
- 키: 가구당 하나, 키체인. 가족 배포 시 게이트웨이 가구별 키+예산. 개발자 키를 앱에 넣지 않음.

## 3. 미구현

### A. 수집 (폰 필요) ★★★
- [ ] ★ 케이뱅크 목록 화면 파서 (로그인 상태 유지 켜고, 목록 한 번 보기).
- [ ] ★ 토스: 토스뱅크 목록 + 자산 탭(토스증권·삼성증권·카카오페이증권 총액).
- [ ] ★ KB 마음편한통장·적금: 거래내역조회 계좌 드롭다운으로 순회. transactions에 `account` 컬럼, uid에 계좌 포함.
- [ ] ★ 카카오 35일 소급 (`TX_DAYS=35 am.py snapshot KAKAO`).
- [ ] 토스증권 API 키 발급(사용자)·IP 등록 → `am.py snapshot TOSSINVEST` 검증.
- [ ] 재연결을 OCR 탭 대신 AXPress로(`phone reconnect` 이미 Swift에 있음, am.py 연결).
- [ ] 잔액 스냅샷 vs 사슬 마지막 잔액 불일치 경고 한 줄.
- [ ] ★ 자동 대사(내 계좌 간 이체 짝짓기): 금액 같음 + 방향 반대 + 시각 ±N분 + 후보 유일 → 자동 확정, 둘 이상이면 미관측으로 두고 봇이 버튼으로 질문. 확정 시 분개의 양끝이 실제 두 계좌가 되고 양쪽 미관측이 동시에 0으로 닫힘(자기 검산). 양쪽 계좌 수집이 전제.
- [ ] 이체 시 "받는분 통장표시" 규칙(예: "케이뱅크→AI")을 쓰면 계좌번호 없이 출처가 박힘 — 사용자 습관, 파서는 이미 읽음. 실무의 적요 관행과 같음.
- [ ] `report.py timeline`을 결산 뒤 자동 실행.

### B. 일일 결산·봇 (폰 불필요) ★★
- [ ] ★ 수집 시작을 시계가 아니라 밤 시간대 `CONNECTED` 이벤트로. `IN_USE`면 즉시 중단, 재개.
- [ ] ★ `TX_DAYS`를 "마지막 성공 마감 이후"로.
- [ ] ★ 수집 중 알림 큐(로그인 요청만 즉시), 마무리에 한 줄.
- [ ] 아침 한 줄(어제 건수·합계, 순자산 방향, 못 읽은 앱 먼저), 월요일 자동 보고서 + 한 줄.
- [ ] 하루 하나의 질문: 큰 지출 고르기, 자본 버튼 여섯(개인) / 계정과목 여덟+개인 용도(사업·법인), 답 → 라벨·결과물 칸.
- [ ] ATM 인출 직후 "뭐 하려고?", 1주 뒤 세어 보기.
- [ ] 세어 보기 질문: 사람별 채팅, 되읽기 확인, 한글 숫자 파서, 3일 무응답 넘김, 하루 하나 큐 우선순위.
- [ ] 말투 설정(사람별, 부모님 존댓말 기본), 지난 잔액 스포일러.
- [ ] 키 읽기를 키체인 우선으로(`security find-generic-password`), `.env`는 폴백.

### C. 장부 모델 (Swift Rules/Ledger, 일부는 am.py 스키마) ★★
- [ ] ★ `data/entities.json`: 마디(폴더/실체, 실체 유형, 지분율, 자식), 계좌 속성(사람, 통화, 허용오차, 기본 현금 계좌).
- [ ] ★ `classify(line, tree)`: 가장 가까운 실체 조상이 다르면 "주머니 사이", 이름 필수. 저장은 양끝 계좌 id + 선택 속성(귀속, 이름).
- [ ] 주머니 사이 선의 이름 목록·방향·잔액 집계(`crossBalances`): 급여/배당/경비정산/가지급금/가수금/출자/인출/증여/대여/상환. 법인 마디 "주머니 사이" 탭.
- [ ] 현금 계좌: 세어 본 값 snapshots `source=count:<사람>`, 현금 전표 `source=manual:<대화 id>`, 현금과부족(열린 잔액), 허용오차, 사슬 없으면 기대값 없음, 짝짓기 규칙, 관측 실선+기대 점선.
- [ ] 외화: 통화당 계좌, 매매기준율 출처 저장, 외화환산손익 자동 선.
- [ ] 부채: 카드·대출 계좌, 재무상태표 오른쪽.
- [ ] 부동산: 평가 관측(공시가·실거래·시세·감정) + 담보대출·전세보증금. 데이터 출처(실거래가 API, 공시가 API 등) — 조사 결과 대기.
- [ ] 기초잔액·자본 분개, 시산표(모든 계좌에 월초 값이 생긴 뒤).
- [ ] 원장(계정별) 뷰 — 계좌가 열 개를 넘으면.
- [ ] 법인 소액현금: 사진 한 장씩 되읽기, 증빙 등급(적격/간이/없음), 현금출납장 CSV 내보내기.
- [ ] 세무 상수 표(`Rules.tax(연도)`): 간이영수증 3만원, 증빙불비가산세, 접대비, 보관 5년, 가지급금 인정이자율, 현금영수증 10만원 — 전부 세무사 확인 뒤.
- [ ] 용도 라벨 LLM 제안 + 사용자 확인 통로(지금은 가맹점 정규식).
