# 세움터: 현재 가입 단계에서 준비하고 필요한 인증 뒤 이어가기

이 절차는 가족이 같은 탐색 방법을 재사용하기 위한 안내다. 계정·인증·소유 권한은 이번 작업 당사자에게만 속한다. 다른 가족이 로그인한 세션을 그 사람의 계정으로 계속 사용하지 않는다. 세션과 당사자가 다르거나 불명확하면 계정 구분부터 확인하고, 사용할 본인 세션을 준비한다. 자격 증명·비밀번호·인증용 주민(법인)등록번호·인증서 암호·OTP뿐 아니라 이름·연락처·주소 등 실제 사용자 입력값도 이 문서, 발자국, 공개 실행 기록에 적지 않는다. 공개 기록에 저장하지 않는 것과 현재 허용된 폼에 입력하는 것은 구분한다.

## 시작과 화면 읽기

1. 사용자가 Windows를 지정했거나 현재 작업에서 공식 Windows 실행 파일이 필요한 사실을 이미 확인했다면 기존 Parallels의 Windows 브라우저를 재사용한다. 이미 열린 세움터 창을 `windows_screen`으로 먼저 읽고 필요한 경우에만 `windows_open("https://www.eais.go.kr/")`으로 진입한다. 매 재개 때 Mac의 막힌 인증 경로를 다시 시험하거나 설치를 반복하지 않는다. 그 외에는 Mac Chrome에서 홈페이지를 열어 현재 주소·본문·대화상자를 읽는다. 정부 사이트라는 분류만으로 Windows 필요 여부를 추정하지 않는다.
2. Mac 브라우저는 최신 DOM의 실제 역할·이름·라벨로 대상을 찾고, Windows는 `windows_screen`의 최신 화면과 OCR로 대상·좌표를 확인한다. 현재 Windows 도구에는 게스트 DOM 조회 기능이 없다. 과거의 노드 ID나 화면 좌표를 다음 세션의 선택자로 저장하지 않는다. 인증 URL에 붙는 `tx` 같은 세션 값은 저장·재생하지 않고 현재 화면의 진입점으로 새 세션을 만든다.
3. 현재 계정이 이번 당사자의 계정인지와 필요한 작업을 세션 문맥으로 확인한다. 이미 명확한 사항을 다시 묻지 않는다. 일반 메뉴 탐색, 안내 읽기, 조건 선택과 건축물 검색을 계속하고, 이미 제공되었으며 이 사이트 사용이 허용된 이름·연락처·주소 등 일반 폼 정보는 현재 작업 범위에서 자동 입력한다. 필요한 정보가 없을 때만 묻는다.
4. `로그인` 또는 `회원가입`이라는 글자를 보았다는 이유만으로 사용자에게 전부 넘기지 않는다. 현재 화면의 실제 진입 경로를 열고 방법·요건·입력 필드를 확인한 뒤, 아래의 실제 사용자 단계까지 준비한다. 아직 관찰하지 않은 버튼명·회원 유형·인증 방식·URL은 추측해 조작하지 않는다.

## 회원가입 준비와 빠른 재진입

1. 세션 문맥의 당사자·기존 계정 여부·회원유형·사용할 프로필·이미 승인된 범위를 이어받는다. 이미 알려 준 정보를 재질문하지 않는다. 개인사업자라고 지정했다면 사업자(개인 및 법인) 경로를 사용하며 일반회원 경로로 고정하지 않는다. 현재 화면의 주소와 유형·단계 제목, 대화상자를 함께 읽고 아래 상태에서 이어간다. URL만으로 회원유형이나 성공을 판정하지 않는다.

| 현재 화면 | 이어갈 작업 |
|---|---|
| 가입 유형선택 `/moct/awp/aba01/AWPABA01F01` | 현재 표시된 일반·사업자·외국인 중 이번 세션에서 지정한 유형을 선택한다. |
| 약관동의 `/moct/awp/aba01/AWPABA01F02` | 일반회원과 사업자회원이 같은 경로를 사용하므로 선택한 유형과 화면 내용을 함께 확인한다. 기존 승인 범위의 필수 항목만 선택하고 다음 단계로 준비한다. |
| 사업자인증 `/moct/awp/aba01/AWPABA01F04` | 가입을 처음부터 반복하지 않고 아래 사업자 기본정보 준비로 이어간다. 현재 프로필 입력 상태와 번호 처리 동의·공동인증창 상태를 확인한다. |
| 열린 공동인증서 창·휴대폰 인증 대기 | 같은 요청이 유효하면 준비를 반복하지 않고 실제 당사자 인증만 기다린다. 완료 보고 후 새 화면으로 결과를 확인한다. |
| 명시적인 세션·토큰 만료 | 만료된 요청을 정리하고 현재 가입 진입점에서 같은 유형·목적의 준비를 다시 진행한다. 과거 인증 URL을 직접 재생하지 않는다. |
| 인증 이후 정보입력·가입 완료 또는 다른 화면 | 최신 화면의 안내와 결과를 읽고 허용된 입력·다음 작업을 이어간다. 아직 확인하지 않은 URL이나 버튼을 추측하지 않는다. |

2. 약관은 현재 내용과 필수·선택을 구분한다. 같은 당사자·사이트·가입 목적과 내용에 대한 필수 동의를 이미 승인받았다면 같은 승인을 다시 묻지 않고 그 범위만 처리한다. 선택 개인정보 수집·마케팅을 자동 선택하거나 전체 동의로 묶지 않는다. 새 약관·새 민감 접근 권한과 가입 최종 확정은 공통 절차의 사용자 단계로 남긴다. PASS 인증 동의를 세움터 가입 약관이나 최종 가입 확정의 승인으로 확대하지 않는다.
3. 허용된 일반 입력과 실제 인증창 준비를 먼저 마친다. 사업자회원은 본인인증 전에 상호·사업자등록번호 입력이 필요하므로 아래 Windows 전용 프로필 경로로 준비한다. 이미 허용된 번호 처리 동의·인증창 열기는 재질문 없이 이어간다. 그 다음 실제 자격 증명·비밀번호·인증서 암호·인증용 주민(법인)등록번호·OTP·생체 인증·CAPTCHA가 필요한 필드와 아직 승인받지 않은 새 동의·권한만 당사자에게 넘긴다. 인증값을 채팅이나 플레이북에 보내 달라고 요구하지 않는다.
4. 사용자가 `했어`라고 알리면 대기하던 요청의 새 화면을 즉시 확인한다. 이미 다음 단계면 그 단계에서 이어가고, 같은 요청의 결과 확인 버튼이 필요하면 한 번 누른 뒤 결과를 읽는다. 만료가 명시되면 기존 승인 범위에서 재준비한다. 새 요청은 만료된 요청의 정리와 새 입력 상태를 확인한 뒤 별도 실행으로 다루며, 실제 휴대폰 승인·인증서 암호 등만 다시 당사자에게 넘긴다. 사용자의 완료 발언만으로 인증 성공이나 새 동의 승인을 추정하지 않는다.
5. 인증 이후 제공되고 사용이 허용된 일반 가입 정보는 입력하고, 필요한 정보가 없을 때만 묻는다. 실제 비밀번호 설정·추가 인증·최종 가입 확정은 현재 요구되는 사용자 단계에서 처리한다. 가입 완료 안내 또는 가입 이후 화면을 확인하기 전에는 가입 성공으로 적지 않는다. 성공이 확인되면 원래 로그인·도면 작업으로 이어간다.

이 표와 단계는 현재 화면에서 재진입할 위치를 찾는 절차다. 브라우저용 자동 콤보 재생 엔진이나 백그라운드 인증 재개를 제공하지 않으며, 문서·manifest의 단계 선언을 현재 버전의 재생 성공으로 표시하지 않는다.

### 2026-09-08 확인한 가입 준비 범위

- Mac Chrome 홈페이지의 `회원가입`에서 `일반회원 가입하기`를 열어 약관동의 화면 `/moct/awp/aba01/AWPABA01F02`에 도달했다. 유형 선택 화면에는 일반회원·사업자·외국인 경로가 표시되었다. 이 Mac 관찰에서는 사업자·외국인 경로의 실제 다음 화면을 확인하지 않았으며, 후속 Windows 사업자 경로는 아래에 별도로 기록한다.
- 화면의 안내 순서는 `유형선택 → 약관동의 → 본인인증 → 정보입력 → 가입완료`였다. 이 안내는 각 단계의 실기 완료를 뜻하지 않는다.
- 약관 화면의 필수 이용약관, 필수 개인정보, 선택 개인정보 체크박스는 모두 미선택으로 유지했다. 약관 동의·본인인증 진입·가입 완료는 수행하지 않았다. 당사자의 동의와 필요한 실제 입력을 마친 뒤 새 화면을 확인해야 이어갈 수 있다.
- 당시 가입 약관은 2026-06-29 개정으로 표시되었고 자동 로그인에 대한 사전 허락 관련 조항이 있었다. 이 가입 약관의 미동의 상태는 아래 통신사PASS 인증의 필수 동의 승인과 별개다. 로그인 자격 증명과 휴대폰 본인 인증은 당사자가 직접 처리하며, 현재 인증 요청에 대해 명시적으로 승인된 동의·요청 버튼은 아래 절차에 따라 대행할 수 있다.

## 로그인 준비와 복귀

1. 현재 화면의 로그인 진입점을 열고 실제로 표시된 로그인 방법, 필요한 입력, 오류·권한 대화상자를 읽는다. 가입이 필요하면 위 절차로 이동한다. 자격 증명을 입력하지 않고도 가능한 방법 선택과 일반 안내 이동은 진행한다.
2. 당사자가 선택한 방식의 실제 입력·인증 단계까지 준비한다. 방법이 여러 개이고 선택이 작업 결과에 영향을 주면 세션에서 이미 선택된 수단을 사용하고, 필요한 선택 정보가 없을 때만 짧게 확인한다. 자격 증명·비밀번호·인증서 암호·인증용 주민번호·OTP·생체 인증·CAPTCHA는 당사자가 직접 처리한다. 이번 인증 요청의 필수 동의와 인증요청 전송을 명시적으로 승인받았다면 그 범위에서 대행하며 같은 승인을 다시 묻지 않는다. 비회원 폼 등에서 이름·연락처·주소가 필요하면 이미 제공되었으며 이 사이트 사용이 허용된 값을 현재 작업 범위에서 자동 입력하고, 필요한 값이 없을 때만 묻는다.
3. 사용자에게 넘길 때는 `현재 화면 → 필요한 행동 → 완료 후 확인할 상태`를 설명한다. 새 민감 접근 권한을 허용해야 하는 경우 대상과 권한을 보여 주고 사용자의 승인을 받는다. 이미 세션에서 승인된 사항은 반복해서 확인하지 않는다.
4. 인증 대기 중 사용자가 `했어`, `완료했어`처럼 휴대폰 단계를 마쳤다고 알리면 그 대기 단계로 복귀한다. 현재 URL·DOM·대화상자를 다시 읽고 같은 요청의 `인증완료` 버튼을 찾아 한 번 누른다. 버튼을 대신 눌러 달라는 기존 요청이 있으면 재확인을 요구하지 않는다. 휴대폰 인증 완료 발언이나 버튼 클릭 자체를 웹 로그인 성공으로 처리하지 않는다. 아래 완료 확인 절차로 성공·휴대폰 미완료·만료·응답 미확인·인증 후 회원가입 필요를 구분한다.
5. 돌아갈 작업이 건축물현황도 발급이면 그 화면으로 복귀한다. 세션 만료·추가 인증이면 실제로 요구하는 단계만 다시 준비한다. 인증 실패를 성공으로 처리하거나 다른 가족의 계정으로 우회하지 않는다.

### 간편인증 제공자 선택과 통신사PASS

1. 사용자가 인증 방법이나 제공자를 바꾸면 최신 선택에 맞춰 준비하고 이전 방법의 준비 요청을 반복하지 않는다. 금융인증서·공동인증서·은행의 민간 간편인증은 별도 방식이다. [Any-ID 공식 개인 이용방법](https://www.anyid.go.kr/rprssite/utztnmthd?type=idv)은 금융인증서를 지원 수단으로 안내하지만, 세움터에서 실제로 제공하는지는 현재 로그인 화면에서 따로 확인한다. 2026-09-08 관찰에서는 세움터의 금융인증서 선택 경로를 확인하지 못했다.
2. 간편인증 제공자는 창을 다시 열 때 순서가 달라질 수 있다. 현재 화면의 실제 제공자 라벨·아이콘을 찾아 선택하며 이전 순번·좌표를 재사용하지 않는다. 통신사PASS를 요청받았다면 `삼성패스`와 구분한다. 빨간 PASS 아이콘만으로 완료를 판단하지 말고 선택 후 `통신사PASS` 헤더, 선택 테두리와 통신사 필드를 확인한다.
3. 이번 실기에서는 OCR 텍스트 위치 클릭 뒤 변화가 없었고, 새로 관찰한 빨간 PASS 아이콘 중앙 클릭 뒤 선택을 확인했다. 텍스트 클릭이 항상 실패하거나 같은 좌표가 항상 성공한다고 일반화하지 않는다. 동작 후 최신 화면으로 선택 상태를 검증한다.
4. 이름·생년월일·휴대폰·통신사는 이번 당사자의 기본정보 프로필에 등록해 전용 `profile_fill`로 입력할 수 있다. `profile_status`로 항목별 등록 여부를 확인하고, 없는 항목은 사용자가 등록을 요청하며 제공한 정보만 `profile_save`로 저장하거나 설정의 자동입력 기본정보에서 직접 등록하도록 안내한다. 대화 기록에 남기고 싶지 않은 정보는 앱에서 직접 등록한다. 다른 가족은 별도 `profile_id`로 구분하고 원문을 상태 응답으로 요청하지 않는다.
5. 첫 지원 양식은 Windows의 `eais_pass`이며 `name`, `birth_date`, `phone`, `carrier`를 한 항목씩 입력한다. 최신 화면에서 각 입력칸의 중심 `x`, `y`를 확인한다. 도구가 세움터 주소·통신사PASS 헤더·항목 라벨과 위치를 다시 검증하며, 휴대폰은 고정된 010 뒤 입력칸, 통신사는 드롭다운을 가리켜야 한다. 양식 검증이나 입력 확인이 실패하면 반복 입력하지 않는다. 이 전용 경로의 값은 도구 응답·발자국·지속 캡처에 남기지 않는다.
6. 기본정보 입력 후 네 항목이 이번 당사자의 프로필과 일치하는지 확인하고 필수·선택 동의를 구분한다. 현재 통신사PASS 요청의 필수 동의 3개와 `인증요청` 전송을 사용자가 명시적으로 승인했다면 그 항목만 선택하고 요청을 한 번 전송한다. 같은 승인을 반복해서 묻지 않으며 선택 동의·마케팅이나 다른 목적의 새 동의까지 승인된 것으로 확대하지 않는다. 사이트의 요청 전송 메시지를 읽어 전송 여부를 확인한 뒤 휴대폰 PASS 단계로 넘긴다.
7. 휴대폰 PASS의 OTP·비밀번호·생체 인증·최종 본인 승인은 당사자가 직접 처리한다. 사용자가 입력·인증 중이면 중복 입력이나 별도 인증요청을 보내지 않는다. 대기 중인 제공자와 원래 작업은 현재 세션 문맥으로 유지하되 입력값·휴대폰 인증 내용·세션 토큰은 플레이북이나 발자국에 저장하지 않는다.

### `했어` 이후 인증완료와 원래 작업 재개

1. `human-auth`에서 사용자가 휴대폰 인증을 마쳤다고 알리면 `complete-auth`로 이어간다. 새 화면에서 현재 제공자와 요청 대기 상태, 오류·만료 안내를 확인한다. 이전 화면 좌표나 오래된 인증 URL로 버튼을 누르지 않는다.
2. 같은 요청의 `인증완료` 버튼이 표시되어 있고 만료 안내가 없다면 최신 화면에서 버튼을 찾아 한 번 누른다. 단순한 응답 지연에는 자동으로 연타하거나 새 인증요청을 보내지 않는다. 화면이 바뀌는지와 표시된 응답을 새로 관찰한다.
3. `verify-login`에서 결과를 구분한다. 로그인 요구가 사라지고 인증된 작업 화면 또는 명시적인 로그인 상태가 보이면 로그인 성공으로 확인하고 원래 작업을 재개한다. 아직 휴대폰 인증이 끝나지 않았다는 응답이면 같은 요청의 대기 단계로 돌아간다. 변화나 결과가 확인되지 않으면 `인증완료 응답 미확인`으로 기록하고 반응 원인을 확인하며 성공을 추정하지 않는다. 인증 대기를 넘어 `세움터 회원이 아닙니다. 회원가입 후 이용하세요.`처럼 회원 여부 결과가 나오면 `인증 후 회원가입 필요`로 구분한다. 이는 로그인 성공이나 휴대폰 미완료가 아니므로 PASS 인증을 추가 요청하지 않고 원래 작업의 회원가입 준비로 이어간다.
4. 세션·토큰 만료가 명시되면 그 요청은 재사용하지 않는다. 만료된 인증창을 닫고 현재 로그인 진입점으로 새 세션을 만든다. 제공자 순서가 바뀔 수 있으므로 라벨을 다시 찾아 선택하고 일반 정보의 일치와 만료 원인 해소를 확인한 뒤 요청을 재개한다. 같은 당사자·제공자·필수 동의·목적에 대한 기존 명시 승인은 유지하되, 내용이나 권한 범위가 달라진 새 동의는 따로 확인한다. 재전송 성공 메시지를 확인한 뒤 새 휴대폰 인증 대기로 돌아간다.
5. Any-ID의 선택적 사용자 등록과 세움터 회원가입은 별개다. Any-ID 등록 팝업이 나왔다고 세움터 가입이나 로그인이 완료됐다고 보지 않는다. 선택 등록에 대한 승인 없이 새 등록을 진행하지 않으며 현재 화면과 세션 의사에 맞게 처리한 뒤 세움터의 결과를 다시 확인한다. 세움터 가입이 필요하면 현재 화면의 `회원가입 후 이용하기` 같은 진입점에서 가입 유형·필수 정보·약관을 준비한다. PASS 필수 동의 승인을 새 세움터 가입 약관이나 가입 최종 확정의 승인으로 확대하지 않는다.
6. 로그인된 상태가 확인되면 저장해 둔 원래 작업, 예를 들어 건축물현황도 발급 준비로 복귀한다. 가입 필요 분기에서도 원래 작업의 목적을 유지하며 가입 준비와 실제 당사자 단계를 처리한 뒤 로그인 상태를 다시 검증한다. 도면 신청·발급 완료 여부는 그 이후 화면에서 별도로 검증한다.

## 사업자회원 가입의 기본정보 준비

사용자가 개인사업자라고 지정하면 회원유형에서 사업자(개인 및 법인) 경로를 선택한다. 개인사업자 상호를 다른 법인명이나 가족의 사업자로 추정하지 않는다. 현재 사용 대상의 `profile_id`를 정하고, 사용자가 저장을 요청하며 직접 제공한 상호·사업자등록번호만 `profile_save`의 `business_name`·`business_registration_number`로 저장한다. 번호만 제공됐으면 번호부터 저장하고 모르는 상호만 확인한다.
